# Webの認証ワーカーと更新トークンの復元

## 問題と方針

`offline_access`で取得した更新トークンを保存しない実装では、再読み込み後にアクセストークンだけを復元し、期限前に再認可していた。単純に保存すると、sessionStorageをコピーした複製タブが同じ更新トークンを送る危険がある。AuthZはこの再利用を検知すると、同じclient・ユーザーの他端末のトークンまで失効させる。

同一オリジンの更新処理を、ビルドごとに同じ名前を使うSharedWorker（`zoo-oidc:`とモジュールURLの組み合わせ） に集約する。タブは更新をワーカーへ依頼し、同じセッションの更新要求には最新の結果を共有する。タブ内のPromise共有も維持し、同一画面からの重複した依頼を抑える。定期ポーリングは追加しない。

## 保存とタブの復元

ログイン時にランダムな`refreshSessionId`を発行する。sessionStorageにはトークンとこの識別子を保存し、再読み込み・タブ複製後も同じ更新セッションとして扱う。アクセストークンが期限切れでも、識別子と更新トークンがあれば復元する。認証設定の束縛、ログアウトのマーカー、認証操作の世代検査は維持する。既存の保存情報には更新トークンがないため、更新後に一度認可をやり直してから新方式になる。

SharedWorkerも最後のタブが閉じると終了し得るため、最新の更新結果と絶対期限（`expiresAt`）をIndexedDBへ保存する。古い更新トークンを持つタブが依頼しても、ワーカーにある最新のトークンだけを使う。保存済みアクセストークンの期限に余裕があれば通信せず同じ結果を返す。ページはWorkerから渡された絶対期限をそのまま使い、ページ凍結やメッセージ配送の遅延で寿命を延ばさない。更新応答の`expires_in`が省略されている場合だけ、従来の直接交換と同じ300秒を使う。指定された不正な値は拒否する。ID tokenは保存前にissuer・audience・期限を検査し、キャッシュから返すときは期限切れID tokenの再利用を避けるため省略する。ページ側でも通常の検査を維持する。

保存先は更新セッションごとに1行で、更新回数に応じて履歴を蓄積しない。更新トークン本体を含むため、同一オリジンのコードとブラウザーのサイトデータが信頼境界になる。タブを閉じてもワーカーの保存状態は残るが、セッションを選ぶランダムな識別子はsessionStorage内に置き、別の新規タブでアカウントを自動選択しない。

24時間以上使われていない資格情報を掃除の対象にする。Workerは初回の更新依頼時と、その後は更新依頼があった時点で最短1時間ごとに未使用行を探し、セッションごとのロック内で最終利用時刻を再確認して資格情報を消す。古い行は削除せず`ended`へ置き換え、複製タブによる復活を防ぐ。セッション破棄（APIの401や更新失敗など）でも同じ終了処理を依頼する。保存先を使えず終了できなかった行は、この掃除の対象となる。

タブを閉じた後にWorkerが起動しなければ掃除は実行されないため、24時間経過した瞬間に物理的に削除される保証はない。AuthZ側の更新トークンは発行ごとに最大30日有効であり、この変更ではrevokeを呼ばない。共有端末ではタブを閉じるだけでなくログアウトする。IndexedDBにはトークン本体を暗号化せず保存する。同一オリジンのXSSから利用できる鍵を同じ保存先へ置いても読み取りを防げないため、暗号化をXSS対策とは扱わない。過去の行の資格情報を掃除し、残存範囲を減らす。ブラウザーのサイトデータへアクセスできる利用者や同一オリジンのコードからの読み取りを防ぐ仕組みではない。

## rotation・終了・配備の競合

ワーカー内のWeb Locksで、セッションごとに更新・ログアウトを直列化する。配備によってWorkerのURLが変わり旧・新Workerが併存しても、同じロックとIndexedDBを使うため更新トークンを二重送信しない。issuer・token endpoint・client・resourceの束縛が異なる依頼は拒否する。

送信前に`pending`状態をIndexedDBへcommitする。更新結果を保存できれば`ready`へ戻す。Workerの読込失敗はerrorイベントで待機中の依頼へ即座に通知する。ワーカー終了・通信切断・タイムアウト・不正応答で結果が不明なら、古いトークンを再送せず再認可する。SharedWorker・Web Locks・IndexedDBが使えない環境では更新トークンを保存しない。この場合も、タブごとの更新へ戻して二重送信することはせず再認可する。

ログアウトではワーカーの資格情報を消し、`ended`状態だけを残す。複製タブが古い保存情報で更新セッションを復活させるのを防ぐため、終了記録を時間で消さない。Workerを起動できない場合も、終了状態の保存だけは同じロックとIndexedDBを使ってページから行える。終了状態の保存に失敗した場合は、既存のログアウト復旧画面から再試行し、永続状態を消せるまで画面遷移しない。発行済みJWTの期限やAuthZの`offline_access`の失効仕様は変更しない。

## 他のクライアント

Android・iOS・TUIにはブラウザーのタブ複製とsessionStorageの破棄がないため、このWorkerを導入しない。各実装の更新トークンの保存を確認し、TUIの既存のファイル保存・プロセス間ロック、Android・iOSの専用保存先を維持する。APIとOIDCの要求形式、AuthZのrotation設定は変更しない。この変更によるTUIの配布物の変更はなく、版は上げない。

## 検証と外部仕様

再読み込み後・アクセストークン期限切れ後の更新、複製タブの並行更新の集約、最新の更新トークンへの追従、Worker再起動、残存期間、ログアウト・アカウント切替、保存失敗、通信失敗、不正ID tokenを検証する。実ブラウザーでは複数のSharedWorker接続と、別のWorkerインスタンスから同じIndexedDBの状態を復元する経路を確認する。AuthZ本番との結合試験は別途とする。

SharedWorkerの対応と寿命は[MDNのコンストラクター解説](https://developer.mozilla.org/en-US/docs/Web/API/SharedWorker/SharedWorker)と[Workerの寿命](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers#shared_worker_lifetime)を参照する。ブラウザーの寿命延長機能には依存しない。
