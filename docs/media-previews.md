# メディア・添付ファイルのプレビュー

React のチャット添付、暗号化添付、Home・ActivityPub の投稿は `MediaPreview` を共有する。
Android にもこの部品と解析処理をローカルのWebView用バンドルとして同梱する。
Androidの通常添付とAPub投稿にも、アプリ内でプレビューを開く操作を追加する。

| 形式 | 表示 |
| --- | --- |
| PNG・JPEG・WebP・GIF、通常添付のAVIF | 画像と拡大表示 |
| PDF | PDF.jsのキャンバス描画、縦スクロールによる連続表示、前後ページボタンとページ番号入力によるジャンプ。日本語用CMap・JPEG 2000などのデコーダー・標準フォントをWeb/Androidへ同梱し、外部CDNやPDFプラグインに依存しない |
| MP4・WebM・Ogg・QuickTime動画、MP3・MP4・WAV・Ogg・WebM・FLAC・AAC音声 | 標準プレイヤー。対応コーデックはブラウザー・WebViewによる |
| EML・MSG | 件名・差出人・宛先・日時、本文、メール内の添付ファイル |
| TXT・Markdown・CSV・JSON・XML・HTML・ログ・コード・予定表・連絡先などのテキスト | テキスト表示。JSONは整形し、HTMLやコードは実行しない |
| DOCX・XLSX・PPTX、ODT・ODS・ODP | 本文・セルの簡易表示。原本の書式・レイアウト・図表を再現するものではない |
| ZIP | 内部ファイル一覧と個別プレビュー・保存。ディスクへ自動展開しない |

旧形式のDOC・XLS・PPT、RAR・7z・tar・gzip、暗号化された文書やアーカイブなど、対応できない形式はダウンロードを維持する。
SVGを直接埋め込まない。画像のAPubプロキシは従来の対応形式を維持する。

## 読み込みと上限

投稿内の画像は配置先の横幅を使う1列表示とし、拡大時は画面幅に合わせる。
PDF・文書・メール・アーカイブのファイル取得と解析は、プレビューを開いた時点で開始する。
動画・音声は自動再生・事前読み込みを行わない。
センシティブな添付は表示操作まで取得しない。
既存の署名付きURLの共有キャッシュ・期限更新・ダウンロードを使い、メタデータ用APIやポーリングを増やさない。

PDF・文書の取得は12 MiB、アーカイブの展開結果は16 MiB・100エントリー、表示テキストは50万文字、解析・描画の待機は15秒まで。
ZIP内とメール内の添付も共通部品を使い、入れ子は3段までプレビューする。
文書解析は専用Workerで実行し、閉じる・URLが変わる・アンマウント時はWorkerと取得を終了する。
PDFはファイルを1回読み込み、スクロールやページ移動では同じ文書を使う。表示範囲周辺のページだけを描画し、離れたページのキャンバスは解放する。縦スクロール表示は全ページ分の枠を並べるため、1000ページまでを対象とし、超過時はプレビューを表示せずダウンロードを案内する。
PDF.jsのworkerはmodule workerとして読み込むため、`.mjs` をJavaScriptのMIMEタイプ（`text/javascript` など）で配信する。
配信先のnginxはバージョンによって `.mjs` を知らないので、`infra/Dockerfile-frontend-deploy` で `mime.types` に追加し、CIで実際の応答を検証する。
デコーダー・フォント・workerは `/assets/pdfjs/<version>/` に置き、PDF.jsの版が変わったときだけURLを変える。
メールのHTMLはテキストに変換し、外部画像・スクリプト・フォームを読み込まない。
Office XMLのDTDは禁止する。大きなファイルや壊れたファイルはエラー表示とダウンロードにフォールバックする。

APubの受信画像は従来の登録済み画像プロキシを維持する。
ほかの対応形式は画像プロキシへ登録せずHTTPSの配信元から読み込む。
Webでは取得先のCORSや埋め込み制限によってプレビューできない場合がある。
過去に受信時に破棄された非画像添付は、相手からの更新または再取得後に反映される。

## Android

`pnpm --dir frontend install --frozen-lockfile` を行い、通常のAndroid用Gradleタスクを実行する。
`buildMediaPreview` が `pnpm build:media-preview` を実行して `build/generated/media-preview-assets` へ出力し、APKのassetsに含める。
依存の導入・ビルドはAndroid CIの検証・リリースの両方にも設定する。

画像・PDF・動画・音声はAndroidのネイティブ要素で表示する。AVIFのネイティブ表示はAndroid 12（API 31）以降を対象とし、古い端末ではダウンロード操作を表示する。PDFはPdfRenderer、動画はVideoView、音声はMediaPlayerを使う。
PDF・動画・音声は1回の取得を64 MiBまでに制限し、ページ移動やシークで同じ非公開一時ファイルを再利用する。閉じると取得を中断し、一時ファイルとプレイヤーを解放する。バックグラウンド移行時は再生を停止する。
プレビューは画面内に収まる単一のネイティブウィンドウに表示し、アプリ本体の背景ブラーから分離する。
メール・Office文書・ZIP・テキストには同梱の文書ビューアを利用し、Web側のモーダルを重ねない。
この文書用WebViewは外部ページへ遷移せず、同梱assetsと選択中のファイルだけを読み込む。
ファイルの取得はネイティブ側で行い、署名付きURLに認証ヘッダーを付け足さない。
APubの任意URLからプライベートアドレスへ接続しないようDNS解決時に検査し、リダイレクトは追わない。
アカウントのAPIホストは、利用者が設定した接続先として許可する。
画面を閉じた際は取得を中断し、文書用WebViewを親ビューから取り外した後に破棄する。
メール・ZIP内のファイルの保存は、利用者が操作したファイルだけを非公開キャッシュに書き、FileProviderでAndroidの共有画面へ渡す。
共有キャッシュは64 MiBを上限とし、次の保存時に1日より古いファイルを削除する。

TUIにはメディア描画画面がないため、既存の添付名・種類表示を維持し、機能追加・版上げは行わない。
デスクトップは従来の表示を維持する。API・Shape・DBの形式や認可は変更しない。

## 検証

Storybookの `Components/Media/MediaPreview` と関連するブラウザーテストで形式・読み込み・失敗・狭い幅・縦スクロール・前後ページボタン・ページ番号ジャンプを確認する。
`.storybook/fixtures/README.md` にサンプルの由来を記載する。

Androidの端末テスト（`connectedDebugAndroidTest`）でネイティブPDFの複数ページ描画を確認する。CIでは端末テストAPKのビルドまでを行う。Robolectricの回帰テストでは、サイズ上限、読み込み中のキャンセル、一時ファイル削除、文書WebViewの取り外し後の破棄、閉じる・開き直す操作を確認する。
