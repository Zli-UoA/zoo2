# 初期ツアー

ログイン後、そのブラウザーで初めて使うアカウントに6ステップの案内を表示する。
画面を覆うモーダルではなく、実画面の横（狭幅では下）に小さな操作パネルを配置する。
案内パネルの領域を確保し、実際の画面をクリック・入力できる状態に保つ。

1. 開始の案内。
2. チャンネル一覧へ移動し、一覧を枠で示す。利用者が実際にチャンネルを選ぶと次へ進める。未参加の場合は既存の検索・参加・作成を利用できる。
3. 選んだチャンネルの投稿欄を枠で示し、投稿・スレッド・リアクションを説明する。ツアーが投稿や参加を自動実行することはない。
4. 通知画面へ移動し、通知の一覧を示す。
5. 設定のSlack連携タブへ移動し、既存のアカウント紐付け・自分で作った非公開チャンネルの取り込みを説明する。OAuth認可は利用者が既存の連携ボタンから開始する。
6. 一般設定へ移動し、設定タブを示す。

戻る操作でも対応する実画面へ移動する。投稿の案内に戻る際は最後に選んだチャンネルを開く。
遷移失敗時は同じステップにとどまり、再試行できる。
完了・スキップ・Escapeは表示済みとして扱い、ナビゲーションのコンパスボタンから再表示できる。
状態はlocalStorageの `zoo:onboarding:v1:<ユーザーID>` に保存し、端末間では同期しない。
ストレージが使えない場合も閉じられるが、再読み込みすると再表示する。
既存ユーザーにも導入後の初回起動時に表示する。
画面遷移には既存ルーターを使い、既存画面の共有データ取得をそのまま利用する。

Webの画面操作を案内する任意の機能のため、Android・iOS・TUIには追加しない。
TUIのキー操作は既存のヘルプを引き続き使用する。Reactを共有するデスクトップ版には同じ案内が表示される。

Storybookの Flows/Onboarding/Tour では実際のAppShellと画面を実ルーターで切り替える。
初回・完了と再表示・スキップ・モバイル・Slack連携画面と戻る操作を確認できる。
