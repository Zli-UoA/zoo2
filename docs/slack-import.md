# Slack からの取り込みとアカウント連携

Slack のエクスポート ZIP をアップロードすると、Zoo に保存します。保存した ZIP から、チャンネル・メッセージ・スレッド・リアクション・添付ファイルを Zoo に取り込めます。ZIP のアップロードはワークスペース管理者だけが行えます。

- 管理者は、保存した ZIP から任意のチャンネルを取り込めます（この文書の手順）。
- 各メンバーは、Slack アカウントを連携すると、自分が作ったチャンネルを取り込めます（後述の「自分のチャンネルを取り込む」）。

Slack 連携の全体像は Zli-UoA/zoo2#115 を参照してください。

## 1. Slack でエクスポートする

1. Slack の「ワークスペースの設定」→「データのインポート/エクスポート」→「エクスポート」を開きます。エクスポートできるのはワークスペースのオーナーと管理者です。
2. 期間を選んでエクスポートを開始し、届いた ZIP をダウンロードします。
3. ZIP を展開せず、そのまま使います。

ZIP には公開チャンネル（`channels.json`）が入ります。プランや設定によっては非公開チャンネル（`groups.json`）も入ります。DM・グループ DM は取り込みません。

## 2. Zoo にアップロードする

1. Web 版の「Zoo設定」→「Slack 取り込み」を開きます。このタブは管理者にだけ表示されます。Android アプリにはありません。
2. 「ZIP を選んでアップロード」でファイルを選びます。ZIP はブラウザからストレージ（R2）へ直接アップロードされます。上限は `SLACK_IMPORT_MAX_ZIP_SIZE`（既定 5 GiB）です。
3. アップロードが終わると、バックエンドが ZIP を解析します。チャンネル数とメッセージ数が表示されるまで待ちます。
4. 解析が終わった ZIP は「取り込み可能」として保存され、管理者が「ZIP を削除」で消すまで残ります。同じワークスペースの新しい ZIP の解析が終わると、古い ZIP は置き換えられます（取り込み中のものは、取り込みが終わってから置き換えます）。

## 3. 取り込むチャンネルを選ぶ

保存した ZIP のカードに、チャンネルの一覧が表示されます。初めはどのチャンネルも「取り込まない」になっています。取り込むチャンネルだけ、取り込み方を次から選びます。

- **新しいチャンネル**：Zoo にチャンネルを作ります。名前は編集できます。`general` などの予約語や既存チャンネルと同じ名前のときは、`slack-` を付けた名前を提案します。取り込んだ管理者もメンバーに入ります。
- **既存のチャンネル**：既存の Zoo チャンネルに過去ログを追加します。Slack の非公開チャンネルは、Zoo の非公開チャンネルにしか取り込めません（メンバー以外に履歴が見えないようにするためです。新しく作る場合も非公開で作ります）。以前に取り込んだチャンネルは同じ取り込み先に固定され、別のチャンネルへは取り込めません（メッセージの ID は Slack のチャンネルと `ts` で決まるため、取り込み先を変えると過去ログが移らないためです）。以前の取り込み先を削除した場合は、過去ログが削除済みのチャンネルに残っているため、そのチャンネルは取り込み直せません（画面では「取り込まない」しか選べません）。
- **取り込まない**

管理者の取り込み画面には、チャンネルが多いときのために、次の操作があります（React 版の Web だけです）。

- **一括指定**：「すべて新しいチャンネル」「すべて取り込まない」で、全チャンネルの取り込み方をまとめて変えます。以前に取り込んだチャンネルと、取り込み先が削除済みのチャンネルは、同じ取り込み先に固定されているので、「すべて新しいチャンネル」では変わりません。すでに「新しいチャンネル」にしたチャンネルは、編集した名前を保ちます。
- **取り込み後にアーカイブ**：「新しいチャンネル」にしたチャンネルは、チャンネルごとに、または一括で、取り込みが終わった時点でアーカイブできます。既存のチャンネルは、取り込み先でもアーカイブしません。Slack でアーカイブ済みのチャンネルは、指定がなくても、作った取り込み先をアーカイブします。

取り込み先になったチャンネル（新しく作ったものも、既存のものも）には、「Slack から取り込み」の印が付きます。React 版の Web と Compose（Android）の、チャンネル設定に「Slack から取り込み」と表示され、取り込みの種類（「Slack から新しいチャンネルとして取り込みました」か「既存のチャンネルに取り込みました」）と、最後に取り込んだ日付がわかります。種類は最初の取り込みのもので、日付は取り込むたびに更新されます（`channels.slack_import_kind`・`slack_imported_at`）。ヘッダーとサイドバーの一覧には出さず、「チャンネルを探す」でも絞り込みません。TUI には、チャンネル設定の画面がないので、反映していません。この版より前に取り込んだチャンネルにも、マイグレーションで印を付けます。

「取り込む」を押すと取り込みが始まり、進み具合が表示されます。ZIP はそのまま残るので、続けて別のチャンネルを選んで取り込めます。以前に取り込んだチャンネルには「取り込み先: #チャンネル名」と表示されます。もう一度取り込んでもメッセージは重複しません。

取り込みの途中で、新しく作るチャンネルと同じ名前のチャンネルが別に作られた場合は、ジョブが「Channel name '…' is already taken」で失敗します（再試行はしません）。名前を変えて、もう一度取り込んでください。

## 取り込みの内容

- 投稿日時、編集日時、スレッド（返信は 1 階層）、リアクションを保ちます。親の投稿が後から取り込まれた場合も、先に入っていた返信はスレッドに戻ります。
- bot の投稿のカード（attachments）は Zoo のカードとして取り込みます。`https` でないリンクや上限を超える文字列は除くか切り詰めます。カードにできない場合も、本文が空にならないよう代わりの文字列を本文に入れます。Zoo ではカードのある投稿は本文を表示しないので、本文とカードの両方がある投稿は、本文も見出し「Slack」のカードとして先頭に入れます。カードの説明は MFM として描画しないので、このカードではリンクを「ラベル (URL)」の形にします。
- Slack の書式は Zoo の本文に変換します。`<@U…>` は `@ユーザー名`、`<#C…|name>` は `#チャンネル名`（取り込み先の今の名前。非公開のチャンネルに取り込んだものは、参加していない人に名前が見えないよう Slack の `name` のまま）、`<https://…|label>` は `[label](https://…)` になります。
- チャンネルへの参加・トピック変更などのシステムメッセージは取り込みません。本文（`text`）も attachments もなく、Block Kit（`blocks`）にだけ内容がある bot の投稿も、いまは取り込みません。本文がなく、ファイルだけの投稿は、添付として取得しないファイル（外部サービスの共有・削除済みなどの取り込めないもの、サイズや形式で取得をスキップするもの、トークンがなくて保留するもの）の名前を本文にして取り込みます。取得する添付は添付として表示するので、名前は本文に入れません（取得してから実際のサイズが上限を超えたと分かった場合は、そのときにファイル名を本文に入れます。取り込み時に補ったファイル名は、後から添付を取得できたときに本文から外します。投稿者が書いた本文は、ファイル名と同じ文字列でも変えません（補った行は `slack_files.in_content` に覚えています）。通信の失敗などで取得に失敗した場合は、添付ファイルを取得し直すまで空の投稿に見えます）。取り込めないファイルしかなく、名前も分からない投稿は取り込みません。その投稿がスレッドの親なら、返信はスレッドにならずチャンネル直下に並びます。
- Zoo に同じ名前のチャンネルがあるなどで `slack-` を付けた名前を候補にするとき、80 文字を超える場合は、元の名前の一部とハッシュにして 80 文字に収めます。
- ZIP の中の JSON ファイル（`users.json` や、チャンネルの 1 日分のファイル）は、1 つあたり 64 MiB までです。バックエンドのメモリの上限（本番は 512 MiB）の中で読むためです。超えるファイルがある ZIP は解析に失敗します。
- 取り込みでは通知・プッシュ通知・App へのイベントを出しません。取り込み先チャンネルの既存メンバーは、取り込んだ過去ログが既読の状態になります。
- 同じエクスポートを何度取り込んでも、メッセージは重複しません（Slack のチャンネル ID と `ts` から ID を決めています）。
- チャンネルごとに最後に取り込んだ `ts` を記録します。これは後で差分同期（Zli-UoA/zoo2#292）の起点に使います。
- 「添付ファイルを取得」は、失敗した添付に加えて、サイズの上限（`ATTACHMENT_MAX_FILE_SIZE`）や取得を許可する URL（`SLACK_FILES_BASE_URL`）が理由でスキップした添付も取得し直します。Slack の `url_private_download` が 302 を返す場合は、許可した URL へのリダイレクトだけを最大 3 回まで追従し、Bot トークンは最初の URL と同じオリジンにだけ送ります。形式が非対応のものなど、設定では変わらないスキップは戻しません。
- 既存のチャンネルへ取り込むと、その時点の同期カーソルまで、チャンネルのメンバー全員の既読位置が進みます。取り込み前から未読だった古い投稿も既読になります（取り込みより新しい投稿は未読のまま残ります）。
- ZIP は、管理者が削除したとき、新しい ZIP に置き換わったとき、解析に失敗したとき、アップロードが 24 時間以上終わらないまま残ったときにストレージから削除します。アップロード中に削除したときは、ブラウザのアップロードも止めます。別のタブなどでアップロードが続いて、削除した後に ZIP が置かれた場合に備えて、署名付き URL の期限（`ATTACHMENT_PRESIGNED_PUT_EXPIRY_SECS`）から 1 日たったところで、もう一度削除します。

### Slack ユーザーの扱い

Slack ユーザーは、Zoo 上では「無効化済み」のプレースホルダユーザーとして作ります。作るのは、取り込んだチャンネルのメンバー・投稿者・リアクションした人・本文でメンションされた人だけです。ユーザー名は、実在の Zoo ユーザーと取り合わないよう `slack-` で始めます。プレースホルダはログインできず、チャンネルのメンバー一覧と人数・メンバー追加・メンション・DM の候補には出ません。通知も作りません（取り込んだチャンネルで `@here`・`@channel` を使っても、プレースホルダの数だけ通知が作られることはありません。プレースホルダの投稿へのリアクションも通知しません）。Slack アカウントと Zoo アカウントを連携すると（後述）、プレースホルダの投稿は本人に付け替わります。すでに連携済みのユーザーの投稿は、取り込んだ時点で本人の投稿になります。

### 添付ファイル

Slack のエクスポート ZIP には、添付ファイルの実体が入っていません。Zoo は ZIP に書かれた URL を記録しておき、`SLACK_IMPORT_BOT_TOKEN` が設定されていれば Slack から取得して添付ファイルとして保存します。

- トークンは `files:read` スコープを持つ Slack アプリのトークンです（Bot Token `xoxb-…` またはユーザートークン）。
- `ATTACHMENT_MAX_FILE_SIZE` を超えるファイルと、実行ファイルなど添付できない種類のファイルはスキップします。
- 同じファイルを複数のメッセージで共有している場合は、メッセージごとに添付を作ります。
- トークンが未設定のまま取り込んだ場合、添付ファイルは「未取得」として残ります。トークンを設定してバックエンドを再起動した後、取り込み結果の「添付ファイルを取得」から取得できます。履歴に移った過去の取り込みからも取得できます。
- 取得に 3 回失敗した添付は「取得できませんでした」として件数を表示します。トークンの権限などを直した後、「添付ファイルを取得」で取得し直せます。

## サーバーの設定

マイグレーション `20261109000000_create_slack_import.sql`、`20261109001000_index_slack_files_job.sql`、`20261109002000_slack_import_exports.sql`、`20261109002500_slack_files_in_content.sql` を適用してください。取り込み先のチャンネルに付ける印（`channels.imported_from_slack`）には、`20261111000000_channels_imported_from_slack.sql` も適用してください（既存の取り込み先にも印を付けます）。取り込みの種類と日時（`slack_import_kind`・`slack_imported_at`）には、`20261112000000_channels_slack_import_info.sql` も適用してください（すでに取り込んだチャンネルは、ジョブの指定と記録から補います）。取り込みのワーカーはバックエンド本体で動きます。複数台構成でも、DB のリースで 1 件のジョブを 1 台だけが処理します。処理中の台が止まった場合は、リースが切れてから別の台が続きを処理します。

| 環境変数 | 既定値 | 内容 |
| --- | --- | --- |
| `SLACK_IMPORT_MAX_ZIP_SIZE` | `5368709120`（5 GiB） | アップロードできる ZIP の上限（バイト）。5 GiB を超える値は設定できません |
| `SLACK_IMPORT_BOT_TOKEN` | なし | 添付ファイルを取得するための Slack トークン（`files:read`） |
| `SLACK_FILES_BASE_URL` | `https://files.slack.com/` | 添付ファイルを取得してよい URL。scheme・ホスト・ポートが一致し、パスがこの下にあるものだけを、Bot トークンを付けて取得します |
| `SLACK_IMPORT_TMP_DIR` | OS の一時ディレクトリ（`/tmp`） | ワーカーが ZIP をダウンロードして展開するディレクトリ。ZIP はほかのユーザーから読めないよう `0600` で作ります |

ZIP は添付ファイルと同じバケット（`S3_*`）の `slack-imports/` の下に置きます（削除されるまで残るので、その分のストレージを使います）。ブラウザから直接 PUT するため、バケットの CORS で PUT を許可しておく必要があります（`infra/terraform/r2.tf` で設定済みです）。ワーカーは解析と取り込みのために ZIP を `SLACK_IMPORT_TMP_DIR` へダウンロードするので、書き込みができて ZIP と同じ程度の空き容量があるディレクトリが必要です。Kubernetes でルートファイルシステムを読み取り専用にしている場合は、`emptyDir`（`sizeLimit` を ZIP の上限以上にする）をマウントして指定してください。書き込めないと、解析と取り込みは `SLACK_IMPORT_TMP_DIR` を含むエラーで失敗します。zli.chat の本番と Preview では Zli-UoA/zoo2-infra#122（マージ済み）で、`emptyDir`・`SLACK_IMPORT_TMP_DIR`・`fsGroup` を設定します。この PR を配備する前に、本番と Preview の backend にその設定が反映されていることを確認してください。ワーカーは使っている間 ZIP にロックをかけておき、起動時に、どのプロセスもロックしていない `zoo-slack-import-*.zip` を消します。取り込みの途中でコンテナが再起動しても（`emptyDir` はコンテナの再起動では消えません）、前のプロセスが残した ZIP で容量の上限を超えることはありません。

ZIP はブラウザから署名付き URL に直接 PUT するので、フロントエンドの CSP の `connect-src` に、ストレージの公開オリジン（`CSP_STORAGE_SRC`。添付ファイルと同じ設定）が必要です。公開オリジンが Cloudflare のプロキシ配下だと、プランごとのリクエスト本文の上限（Free・Pro は 100 MB、Business は 200 MB）を超える ZIP はブラウザーから PUT できません。そのような大きな ZIP は、ブラウザーを使わず、管理者が手動でストレージへ直接アップロードします（「大きな ZIP を手動でアップロードする」）。プレースホルダのアイコンは Slack のプロフィール画像の URL（`https://avatars.slack-edge.com/…` など）を使うので、表示するには、その配信元を `CSP_APP_IMAGE_SRC`（`img-src`）に追加します。追加しない場合は、既定のアイコンを表示します。`SLACK_IMPORT_BOT_TOKEN` で添付ファイルを取得する場合は、バックエンドから `files.slack.com`（`SLACK_FILES_BASE_URL` のホスト）へ HTTPS で接続できる必要があります。NetworkPolicy などで外向きの通信を絞っている場合は、許可してください。

### 大きな ZIP を手動でアップロードする

Cloudflare の本文上限を超える ZIP は、ブラウザーではなく、バックエンドが使っているストレージのエンドポイント（`S3_ENDPOINT`。Cloudflare のプロキシを通らない）へ、`kubectl` で Secret から認証情報を読んで直接置きます。

1. 設定画面の「Slack 取り込み」タブで、その ZIP を選んでジョブを作ります。ブラウザーからのアップロードは失敗しますが、ジョブは「アップロード中」のまま残ります。アップロード中のジョブは 24 時間で取り消されるので、手順 4 までを、ジョブを作ってから 24 時間以内に終えてください。`GET /api/admin/slack-imports` で、そのジョブの `id` を確かめます（管理者の Bearer トークンが必要です）。
2. バックエンドが使うストレージの設定を、そのシェルの環境変数に入れます。バックエンドのイメージは distroless で、`kubectl exec` で `sh` や `printenv` を実行できないので、Deployment と Secret から読みます。値は画面に出さず、端末の履歴にも残しません。名前空間・Deployment 名・Secret 名は、環境に合わせてください。

   まず、Deployment の環境変数の定義を確かめます。`S3_ENDPOINT`・`S3_BUCKET` の値と、`S3_ACCESS_KEY_ID`・`S3_SECRET_ACCESS_KEY` が参照する Secret の名前とキーが分かります。Secret の値は出ません。

   ```bash
   kubectl -n zoo2 get deploy backend -o jsonpath='{.spec.template.spec.containers[0].env}'
   ```

   次に、バックエンドの名前 `S3_ACCESS_KEY_ID`・`S3_SECRET_ACCESS_KEY` を、AWS CLI の名前 `AWS_ACCESS_KEY_ID`・`AWS_SECRET_ACCESS_KEY` に読み替えて入れます。`<Secret 名>` と `<キー名>` は、上で確かめた値です。

   ```bash
   export S3_ENDPOINT='<S3_ENDPOINT の値>' S3_BUCKET='<S3_BUCKET の値>'
   export AWS_ACCESS_KEY_ID="$(kubectl -n zoo2 get secret <Secret 名> -o jsonpath='{.data.<S3_ACCESS_KEY_ID のキー名>}' | base64 -d)"
   export AWS_SECRET_ACCESS_KEY="$(kubectl -n zoo2 get secret <Secret 名> -o jsonpath='{.data.<S3_SECRET_ACCESS_KEY のキー名>}' | base64 -d)"
   ```

3. `slack-imports/<ジョブの id>/export.zip` というキーに置きます。`aws s3 cp` は、必要に応じてマルチパートで送ります。`Content-Type` は `application/zip` にします（手順 4 で照合します）。

   ```bash
   AWS_REGION=auto aws s3 cp ./export.zip "s3://$S3_BUCKET/slack-imports/<ジョブの id>/export.zip" --endpoint-url "$S3_ENDPOINT" --content-type application/zip
   ```

4. `POST /api/admin/slack-imports/<ジョブの id>/uploaded` を呼びます。ストレージ上のサイズが、ジョブ作成時に送ったサイズと同じか確かめたうえで、解析が始まります。以降はブラウザーからの場合と同じです。

キーやサイズ、`Content-Type` が違うと、4 の確認で失敗します。置いた ZIP はジョブを削除したときに、通常の ZIP と同じように消えます。

この鍵はバケット全体（添付ファイルを含む）の読み書きに使うもので、Secret を読める人は取り出せます。画面共有や録画の中では実行せず、終わったらそのシェルを閉じて、環境変数を残さないでください。鍵を取り出したくない場合は、手元の CLI などで署名付き PUT URL を作って送る方法もあります。

Preview で使うときは、名前空間・Secret 名・`S3_ENDPOINT` の値が本番と同じとは限らないので、確かめてから読み替えてください。

## Slack アカウントの連携

各ユーザーは、自分の Slack アカウントを Zoo アカウントに連携できます。管理者の作業は、最初に Slack アプリを 1 つ作ることだけです。

### 管理者: Slack アプリを作る

Slack の配布アプリ（Marketplace の審査を通っていないもの）は `conversations.history` などのレート制限が厳しいため、ワークスペースごとに社内アプリ（internal app）を作ります（`conversations.history` は差分同期 Zli-UoA/zoo2#292 で使います。いまの版は呼びません）。

1. 管理者のアクセストークンで `GET /api/admin/slack/manifest` を呼び、レスポンスの `manifest` をコピーします（設定画面には、manifest の欄はありません）。アクセストークンは、管理者でログインしているブラウザーのタブの開発者ツールのコンソールで、次を実行すると取り出せます（OIDC を使う構成の場合。トークンは `sessionStorage` の `zoo.oidc.session` に入っています。有効期限が短いので、取り出したらすぐ使い、どこにも貼らないでください）。

   ```js
   JSON.parse(sessionStorage.getItem("zoo.oidc.session")).tokens.accessToken
   ```

   取り出したトークンで、次のように呼びます。トークンを端末の履歴に残さないよう、`read -rs` で入力します。

   ```bash
   read -rs TOKEN && curl -sf -H "Authorization: Bearer $TOKEN" https://<zoo-backend>/api/admin/slack/manifest | jq .manifest
   ```

   初回は `SLACK_OAUTH_REDIRECT_URL` がまだ設定されていないので、manifest の `redirect_urls` は `https://<zoo-backend>/api/slack/oauth/callback` という仮の値です。貼り付ける前に、`<zoo-backend>` を実際のバックエンドの公開 URL に書き換えてください（Client ID と Client Secret は、アプリを作った後でないと分からないので、環境変数は手順 4 でまとめて設定します）。
2. <https://api.slack.com/apps> で「Create New App」→「From an app manifest」を選び、ワークスペースを選んで manifest を貼り付けます。
3. アプリをワークスペースにインストールし、「Basic Information」の Client ID と Client Secret を控えます。
4. バックエンドに次の環境変数を設定して再起動します。

| 環境変数 | 内容 |
| --- | --- |
| `SLACK_CLIENT_ID` / `SLACK_CLIENT_SECRET` | Slack アプリの Client ID と Client Secret |
| `SLACK_OAUTH_REDIRECT_URL` | `https://<バックエンドの公開URL>/api/slack/oauth/callback`。manifest の `redirect_urls` と一致させます |
| `SLACK_TOKEN_ENCRYPTION_KEY` | ユーザートークンの暗号化と state の署名に使う 32 バイトの鍵（base64）。`openssl rand -base64 32` などで作ります |
| `SLACK_TEAM_ID` | 連携を許可する Slack ワークスペースの ID（`T…`）。任意ですが設定を推奨します。設定・変更する前に別のワークスペースで連携したアカウントは、連携済みとして表示されますが、チャンネルの取り込みには使えません（403 `team_mismatch`）。設定画面の案内に従って解除し、連携し直してもらってください。変更する前に始まった取り込みは、そのまま進みます |
| `SLACK_FRONTEND_URL` | 連携後に戻るフロントエンドのオリジン。フロントとバックエンドが同一オリジンなら不要です |

`SLACK_CLIENT_ID`・`SLACK_CLIENT_SECRET`・`SLACK_OAUTH_REDIRECT_URL`・`SLACK_TOKEN_ENCRYPTION_KEY` は 4 つそろえて設定してください。一部だけだと起動時にエラーになり、バックエンドが起動しません。デプロイは、マイグレーションを適用する → 4 つの環境変数を同時に設定する → バックエンドを再起動する、の順に行います。

Slack アプリが求めるスコープは、差分同期（#292）とブリッジ（#293・#294）で使うものも含めて、先にまとめて求めます。スコープを足すたびに、連携済みの全ユーザーに連携を解除してから連携し直してもらう必要があるためです。この版では、連携時の表示名の取得（`users.info`）にしか使いません。

| 種類 | スコープ | 使う機能 |
| --- | --- | --- |
| ユーザー | `users:read` | 連携時に Slack の表示名を取得します（いまの版で使用） |
| ユーザー | `channels:history` `groups:history` `im:history` `mpim:history` | 差分同期（#292）の `conversations.history` / `conversations.replies`。ブリッジ（#293）の `message.*` の購読 |
| ユーザー | `channels:read` `groups:read` `im:read` `mpim:read` | 参加しているチャンネルの列挙（#292） |
| ユーザー | `reactions:read` | `reaction_added` / `reaction_removed`（#293） |
| ユーザー | `reactions:write` `chat:write` | Zoo の投稿・編集・削除・リアクションを、本人として Slack に反映する（#294） |
| Bot | `files:read` | `SLACK_IMPORT_BOT_TOKEN` として、取り込みの添付ファイルを取得する（いまの版で使用） |
| Bot | `chat:write` `chat:write.customize` | Slack と連携していないユーザーの投稿を、Bot が `username` / `icon_url` を付けて代理で投稿する（#294） |

ユーザートークンに履歴スコープを求めるので、連携したユーザーは、自分が参加している会話（非公開チャンネルと DM を含む）の履歴を、Zoo が読めるようにすることに同意することになります。この版では、これらのスコープを使うコードはありません（差分同期とブリッジを入れたときに、はじめて使います）。

Bot は、いまはチャンネルに参加しないので、非公開チャンネルや DM の添付は取得できないことがあります。#293 で Bot の購読（`bot_events`）を使う場合は、Bot の履歴スコープとチャンネルへの参加（`channels:join`）が別に必要になります。ユーザーの権限で購読する方式にするかは、#293 の設計で決めます。

すでにこの版より前の manifest でアプリを作っている場合は、アプリの manifest を更新して再インストールし、各ユーザーに連携を解除してから連携し直してもらいます（`slack_user_links.scopes` で、まだのユーザーを判別できます）。以前に認可したユーザーのトークンは、そのままでは古いスコープのままです。以前に広いスコープで認可したユーザーが、狭めたい場合も、連携を解除してから連携し直してもらいます。

#### 鍵を変えるとき・連携をやめるとき

保存したユーザートークンは、連携を解除したときに Slack 側で失効させるためだけに使います。`SLACK_TOKEN_ENCRYPTION_KEY` を変えると、保存済みのトークンを復号できなくなります。そのまま連携を解除すると Zoo の記録が消えるだけで、Slack 側のトークンは有効なまま残ります（バックエンドのログに `team_id` と `slack_user_id` 付きのエラーを出します）。この鍵は連携開始時の state の署名にも使うので、鍵を変えた時点で連携の途中だった人は、もう一度「Slack と連携」からやり直す必要があります。連携の環境変数を外したり、この機能より前の版に戻したりした場合も、`slack_user_links` のトークンは Slack 側で有効なまま残ります。

鍵を変えるときや連携をやめるときは、次のいずれかを行ってください。

- 鍵を変える前に、連携中のユーザー全員に連携を解除してもらいます。解除したユーザーは、鍵を変えた後に連携し直せます。
- <https://api.slack.com/apps> で Zoo のアプリを開き、ワークスペースからアンインストールして、このアプリのトークンをすべて失効させます。Bot Token も失効するので、このアプリの Bot Token を `SLACK_IMPORT_BOT_TOKEN` に使っている場合は、別のトークンに差し替えるか外してください。続けて使う場合はアプリをインストールし直します。連携をやめる場合は、そのあと `DELETE FROM slack_user_links;` を実行してから環境変数を外すか版を戻します。付け替えた投稿と `slack_users` の対応は残るので、再開したあとも、同じ Slack アカウントは同じ Zoo アカウントにだけ連携し直せます。

鍵が漏れたおそれがある場合は、DB の暗号文から元のトークンを取り出せます。必ず最後の方法ですべて失効させてください。

連携の環境変数をすべて外している間は、トークンを失効できないので、連携を解除できません（404）。設定を戻してから解除してください。

### ユーザー: 連携する

1. 「Zoo設定」→「Slack 連携」で「Slack と連携」を押します。
2. Slack で内容を確認して許可すると、Zoo の設定画面に戻り、連携が完了します。
3. 取り込み済みの過去ログにあなたのプレースホルダがあれば、その投稿・リアクション・参加チャンネルがあなたのものになります。取り込んだチャンネルの本文にあるプレースホルダへのメンション（`@slack-…`）も、あなたのユーザー名に書き換わります。書き換えるのは、通知のメンションと同じく `@` の直前が行頭・空白・開き括弧・`。`・`、` などの区切りのものだけです（`あ@slack-…` のように文字に続くものや、メールアドレス・URL の中は書き換えません）。書き換えると本文の上限（40,000 文字）を超える投稿は、本文もカードも書き換えずに残します。本文を入れたカードの説明は、取り込みのときと同じく 4,000 文字で切ります。新しく参加したチャンネルの過去ログは、取り込んだところまで既読の状態になります（取り込みより後の投稿は未読のまま残ります）。

ゲスト（1 チャンネル・複数チャンネルのゲスト）が連携した場合は、投稿・リアクション・添付だけが本人のものになり、参加チャンネルは移りません。ゲストが参加するチャンネルは管理者が決めるためです。連携後の取り込みでも、ゲストを Slack のメンバーとしてチャンネルに足すことはしません。

Android アプリでは、「Slack と連携」を押すと外部のブラウザーで Slack の認可画面が開きます。アプリへ戻る deep link には未対応なので、連携の完了はブラウザー側で行います（ブラウザーでも Zoo にログインしている必要があります）。アプリに戻ると、連携の状態を読み直し、キャンセルした場合も続けて連携をやり直せます。

1 つの Slack アカウントは 1 つの Zoo アカウントにだけ連携できます。連携を解除すると Slack のトークンを無効にして削除しますが、付け替えた投稿は元に戻しません。管理者が鍵を変えた後に解除した場合は、Slack のトークンは無効になりません（「鍵を変えるとき・連携をやめるとき」）。同じ Slack アカウントは、解除後も同じ Zoo アカウントにだけ連携し直せます。

### ユーザー: 自分のチャンネルを取り込む

連携すると、「Slack 連携」タブに「Slack から取り込む」が表示されます。管理者が保存した ZIP（同じワークスペースの最新のもの）から、Slack で自分が作ったチャンネルを取り込めます。

- 一覧に出るのは、ZIP の `channels.json`・`groups.json` で自分が作成者（`creator`）になっているチャンネルだけです。他の人が作ったチャンネルは、その人が連携して取り込むか、管理者が取り込みます。
- 取り込み先は、チャンネルごとに次から選びます。
  - **既存のチャンネル**：Slack と同じ名前の Zoo チャンネルのうち、自分が参加していて、メンバーを追加できるものだけを選べます。取り込みは ZIP のメンバーもチャンネルに足すため、通常のメンバー追加と同じ権限を求めます（非公開チャンネルでは作成者か管理者だけです）。投稿を管理者に限ったチャンネルには、通常の投稿と同じく作成者か管理者しか取り込めません。Slack の非公開チャンネルは、Zoo の非公開チャンネルにしか入れられません。
  - **新しいチャンネル**：自分が作成者になります。公開・非公開は Slack に合わせます。ゲストは、通常のチャンネル作成と同じく選べません（403）。
  - **取り込まない**
- 以前に取り込んだチャンネル（管理者が取り込んだものを含む）は、同じ取り込み先に固定され、画面では「新しいチャンネル」を選べません。
  - 取り込み先が見えるチャンネルなら、「既存のチャンネル」でそのチャンネルを選びます。既存のチャンネルと同じく、参加とメンバー追加の権限が必要です。以前の取り込み先から外された場合は、取り込み直して戻ることはできません（403）。
  - 取り込み先が見えないチャンネル（参加していない非公開チャンネル。ゲストの場合は、参加していない公開チャンネルも）なら、チャンネル一覧と同じく名前を出さず、以前取り込んだことだけを表示します。このチャンネルは取り込めません（API から「新しいチャンネル」を送っても 403）。
  - 取り込み先が削除されたチャンネルは、一覧に出ません。過去ログが削除済みのチャンネルに残っていて、取り込み直せないためです。
- 「新しいチャンネル」で作るチャンネルの ID は、Slack のワークスペースとチャンネルの ID から決まります。同じ ID のチャンネルがすでにあって、前回の取り込み先として記録されていなければ（`POST /api/channels` で他人が先に作った場合など）、そのチャンネルには取り込みません。利用者の開始は 409、管理者の取り込みはジョブが失敗し、どちらもチャンネル名は出しません。そのチャンネルを管理者が削除してから、取り込み直してください。作成の競合は、INSERT が実際に作れたかで判定するので、確認と作成の間に作られた場合も同じ結果になります。
- 権限は開始時に加えて、ワーカーが取り込み先を決めるときとメンバーを足す直前にも確かめます。開始後にチャンネルから外されると、その取り込みは失敗します。ワークスペース管理者が始めた取り込みは、ワーカーでの確認の対象外です（管理者は取り込み先を管理する権限を持つため、開始時の確認だけです）。
- 別の Slack アカウントと連携済みの Zoo アカウントで連携し直そうとすると、409（`linked_other_account`）になります。切り替えるには、先に連携を解除してください。
- `SLACK_TEAM_ID` で許可していないワークスペースの連携（設定を変える前に連携したもの）では取り込めません。一覧には何も出ず、開始すると 403（`team_mismatch`）になります。設定画面の案内に従って連携を解除し、許可されたワークスペースで連携し直してください。
- 取り込みは管理者の取り込みと同じジョブとしてワーカーが処理し、管理者の「Slack 取り込み」タブにも表示されます。添付ファイルの取得には、管理者の場合と同じく `SLACK_IMPORT_BOT_TOKEN` を使います。

### 仕組み

- Slack から戻るリダイレクト先（`/api/slack/oauth/callback`）ではトークンを交換しません。`code` と `state` を付けて設定画面に戻し、フロントがログイン中のユーザーとして `POST /api/slack/oauth/complete` を呼びます。サーバーは、state に署名された「連携を始めたユーザー」と呼び出したユーザーが一致するときだけ連携します。他人が作った認可 URL を踏まされても、その人の Zoo アカウントに自分の Slack アカウントが連携されることはありません。
- state は 10 分で期限が切れます。
- ユーザートークンは AES-256-GCM で暗号化して `slack_user_links` に保存します。この表は Electric の Shape に含めません。
- 同じ Slack アカウントの連携の保存・解除と、使わないトークンの失効は、アカウントごとのロックで 1 つずつ処理します。Slack は同じアカウントで認可し直すと同じトークンを返すため、連携できなかったときに受け取ったトークンは、そのアカウントの連携に保存されていないことを確かめてから失効させます（別のワークスペースのアカウントでも同じです）。連携を保存する前にもトークンが有効か確かめ、並行した解除などで失効していた場合は、連携せずにエラー（502）を返します。もう一度連携してください。
- 付け替え（連携と、取り込みの最後に行う照合）は、ワークスペースをまたいで 1 つずつ処理します。既存のチャンネルを取り込み先に選べば、別のワークスペースも同じ Zoo チャンネルに取り込めるためです。本文のメンションを書き換えるときは、書き換えるプレースホルダへのメンションを含む投稿だけをロックします。
- 付け替えの間は App へのイベント配送を止めます。

マイグレーション `20261109003000_create_slack_user_links.sql`、`20261109004000_index_slack_reassign.sql` を適用してください。
