# チャンネルノートの Web UI

Web 版のチャンネルノート画面は、既存の Notes REST API（[channel-notes-api.md](channel-notes-api.md)）だけを使う。リアルタイム同期や直リンクは初版の対象外で、一覧・本文は画面を開いたとき、タブ復帰時、手動更新時、書き込み後に取得し直す。

## 入口と権限

- 通常の閲覧できるチャンネルに「メッセージ」「ノート」のタブを出す。DM・暗号化チャンネル・閲覧できないチャンネルにはノートの入口を出さない。
- 公開チャンネルの非メンバーとアーカイブ済みチャンネルは、権限に応じて読むだけにする。
- 書き込みは参加者かつ非アーカイブのときだけ。メッセージの `posting_policy`（管理者のみ投稿など）はノートに適用しない。
- 削除済み一覧・削除済み本文は参加者だけが見られる。アーカイブ済みの参加者も読めるが、復元はできない。
- 参加状態を失った場合は、閲覧権限が残っていても削除済みの入口・一覧・選択・本文を同じ描画から外し、有効ノートの一覧へ戻す。進行中の削除済み取得は中断し、遅れて届いた応答も要求識別で捨てる。閲覧権限を失った場合は本文と下書きを消す。書き込みだけを失った場合は下書きを画面に残し、読み取り専用とコピーだけを提供する。

## 一覧と本文

- PC は一覧と本文を並べ、狭い画面は一覧から本文へ切り替えて「ノート一覧に戻る」を出す。
- 一覧は本文を含まない概要を 1 ページ 50 件ずつ取得する。続きは前ページ最後の項目の `order_token`・`position`・`id` をそのまま `after` に使い、サーバーの順序を保つ。
- ページ取得中に `409`（並び・構成の変更）が返ったら、先頭ページから有限回だけ取り直す。古いページ操作を自動で適用し直さない。
- 本文は選択したノートの取得 API でのみ読む。一覧の再取得では、編集中のタイトル・本文を上書きしない。
- 読み込み中・空・取得失敗・権限不可を別の表示にし、失敗時は再試行できる。 再取得に失敗した場合は前回取得した項目を表示し、その上に失敗と再試行を表示する。 再試行が成功してから続きのページを取得できる。
- 更新ボタンは、いま表示している一覧（有効または削除済み）の読み込み状態だけを見る。削除済み一覧を開く前でも有効一覧を更新できる。
- 同じチャンネル内で新しいメッセージやスレッドを開くルート移動が受理されたら、隠れたメッセージペインのままにせずメッセージタブへ移る。同じメッセージのままスレッドだけが変わった場合も含む。ルートの承認前に発火する `requestMessageJump` は見ないので、移動が拒否されたときはノートと下書きを保つ。
- いまの URL と同じチャンネル・メッセージ・スレッドを指すリンク（スレッドだけのリンクを含む）の通常左クリックでは、URL もルーターの履歴 blocker も動かない。このときだけ `requestChannelLinkReveal` を送り、ノートタブはタブ移動と同じ確認・保存中ガードを通してメッセージへ戻す。別のチャンネル・メッセージ・スレッドへの移動前には送らないので、拒否されたときのノートと下書きは保つ。サイドバーのスレッド一覧も同じ判定を使う。

## 作成・編集・下書き

- 新規ノートは画面内の下書きを作り、明示的に保存したときだけ `POST` する。タイトルは API と同じ Unicode White_Space の前後除去で検証し、本文の長さも API の上限に合わせる。タイトルは加工せず送り、正規化は API に任せる。
- 保存中はタイトル・本文を読み取り専用にし、キャンセル・ノート選択・タブ移動・並べ替え開始などのデータを失う操作を止める。ボタンの連打も同期ガードで 1 回だけ送る。
- 並べ替え準備の全ページ取得中は、新規作成・編集・ノート選択・一覧切替を無効化し、同期 ref でも開始を拒否する。
- 復元中に別のノートを選ぶ、別の一覧へ移る、下書きを始めるなどの後続操作があれば、復元の応答では画面を切り替えず、一覧の再取得だけを行う。復元の 404 でも、後から選んだノートや下書きを消さない。復元後の一覧更新はセッション epoch を確認してから始める。
- 通信断・`408`・`5xx` の新規作成は結果不明として扱い、下書きを残して一覧を取り直す。自動再送はしない。明示的な再送では重複の可能性を表示する。
- 更新・削除は取得時の `version` を送る。更新の `409` は最新本文と下書きを並べ、最新を読み込むか、最新の版で下書きを明示的に上書き保存するかを選ぶ。
- 更新の `404` は無条件に削除と決めない。権限を再確認し、削除済み取得で対象を確認できた場合だけ、書き込み可能なら「新規ノートとして保存」を出す。
- 下書きはブラウザー再読み込みで復元しない。ルート離脱・ブラウザー戻る・再読み込みでは `useBlocker` と `beforeunload` で確認する。ログアウト・アカウント変更・閲覧権限喪失は安全側で即座に本文と下書きを破棄し、遅延応答を適用しない。

## 削除と復元

- 削除前に確認する。
- 削除済み一覧は削除時刻の 24 時間後を UTC の日時として表示する。API の `deleted_at` はカーソルに原文のまま使う。
- 削除済み項目を選ぶと本文を読み、参加者かつ非アーカイブなら復元できる。
- 復元に成功したら通常一覧へ戻り、復元したノートの本文を開く。
- 復元の `404` は有効・削除済みの両一覧を取り直し、期限切れ・復元済み・削除済みのどれかを断定しない。`409`（有効 500 件の上限）は専用の案内を出す。

## 並べ替え

- 並べ替え専用モードを開いたとき、全ページを取得して現在の ID 順を集め、`expected_note_ids` にする。取得中に `409` が返ったら先頭から有限回だけ取り直す。
- PC はドラッグと上下ボタン、狭い画面とキーボードは上下ボタンを使う。変更は明示保存するまで送らない。
- 保存の `409` は最新順を取得し直して表示し、手動でやり直してもらう。古い操作を自動で再適用しない。

## メッセージの既読

- ノート表示中もメッセージペインはマウントしたままにするが、既読書き込みは行わない。スクロール・フォーカス・タブ復帰・遅延コールバックのどの入口でも、既読 hook に表示状態を渡して中央で抑止する。
- メッセージタブへ戻ると従来どおり既読を書き込む。
