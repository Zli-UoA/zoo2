# URLカード・Summaly・画像プロクシ

チャットの投稿・スレッド、Home・投稿詳細・公開プロフィール内のHTTP(S)リンクを最大3件、タイトル・説明付きのカードとして表示します。コード、`<plain>`、MFMのサイレントリンク `?[label](url)` は展開しません。同じURLは1件にまとめます。取得に失敗しても本文リンクは維持します。

カードはタイトル・説明・サイト名（Summalyの `sitename`、未設定時はホスト名）の順に表示します。画像はカードの左側、説明は右側に配置し、画像の読み込みや取得失敗でカードの大きさが変わらないようにします。本文のURLはリンクとして表示し、表示上の `http://`・`https://` は省略します。リンク先は元のURLを維持します。

フロントは指定の [mei23/summaly](https://github.com/mei23/summaly) の `/url?url=...` からJSONを取得します。`title`・`description`・`sitename` を文字列として描画し、`thumbnail` と `icon` を画像プロクシへ渡します。faviconはサイト名の左に表示し、読み込み失敗時は省略します。HTMLやplayerは埋め込みません。SummalyへのリクエストにアプリのCookie・Authorization・Refererを送信しません。

画像はフロントからmedia-proxy-rsへ `?url=<画像URL>` で取得します。小さいサイズに固定される `preview`・`static` は指定せず、プロクシの設定に従って縮小します。本番は最大辺1024ピクセル、Lanczos3、WebP品質90です。アニメーション画像は静止画に変換せず配信します。画像プロクシ未設定時はテキストのカードだけを表示します。元のサムネイルのホストへ直接フォールバックしません。

## このアプリのチャンネル・メッセージのリンク

開いているアプリ自身のチャンネル・メッセージへのリンクは、**チャンネルの一覧（`MfmChannelsProvider`）を持つ画面（アプリのシェル）では、Summaly には送りません。** 行き先を自分のデータから取って、投稿者・本文・チャンネルを持つ埋め込みカードにします。表示と、見られない行き先の扱いは [mfm.md](mfm.md) の「チャンネル・メッセージのリンクの表示」を参照してください。上の3件の制限には、このリンクも数えます。Summalyの設定（`/summaly-endpoint`）の取得は、外部のURLがあるときだけ始めます。

**例外**: チャンネルの一覧を持たない画面（公開プロフィールなど）では、アプリ内のリンクも外部のURLと同じ扱いで、従来どおりSummalyのカードです（同じタブで移動するリンクにはなります）。行き先が見られるかを判定できないため、埋め込みにはしません。暗号化チャンネルの投稿はシェルの中にだけ出るので、暗号化チャンネルの投稿に書かれたリンクは、この例外には当たりません。

Homeのように全行をマウントする画面では、埋め込みカードも、本文中の短い表示も、画面の上下200px以内に近づいてから行き先を取得します。一度取得したあとは、画面から離れても表示を保ちます。取得（と、暗号化かどうかの確認）が10秒たっても終わらないときは、読み込み中の枠をやめて「リンク先を読み込めませんでした」と書き、あとで取得できれば内容に切り替えます（取得の失敗は、`useLiveQuery` の状態に出ないため）。

## エンドポイント

frontendコンテナの実行時環境変数に、それぞれのエンドポイントを指定します。イメージの再ビルドは不要です。

```yaml
env:
  - name: SUMMALY_URL
    value: https://summaly.zliusercontent.com/url
  - name: MEDIA_PROXY_URL
    value: https://media-proxy.zliusercontent.com/
```

起動時にSummalyのオリジンをCSPの `connect-src`、画像プロクシのオリジンを `img-src` に追加します。設定は `/summaly-endpoint` と `/media-proxy-endpoint` から公開のプレーンテキストとして配信します。認証情報やクエリを設定値に含めないでください。Home・投稿詳細・公開プロフィールは、Summaly未設定時・取得中・取得失敗時にはカードを出さず、本文リンクを残します。チャットは従来どおり、取得前・失敗時・未設定時にURLとホスト名の固定サイズのフォールバックカードを表示します。

Vite開発では `VITE_SUMMALY_URL=http://localhost:3030/url` と `VITE_MEDIA_PROXY_URL=http://localhost:12766/` を利用できます。コンテナの実行時設定が優先されます。Composeでも両環境変数をfrontendへ渡します。

取得は同時4件までで、同じURLの要求を共有します。Home・投稿詳細・公開プロフィールでは、IntersectionObserverのrootに最も近いスクロール要素を指定し、その表示範囲の上下200px以内に近づいた投稿だけを取得対象にします。画面付近から離れた場合やタブを非表示にした場合、取得の利用を解除し、最後の利用者がいなくなれば待機中の要求・取得・再試行を取り消します。取得済みのカードは配置を保つために表示を維持し、再表示時には成功キャッシュを利用します。チャットは従来どおりマウント中に取得し、最後のカードがアンマウントされたら取り消します。一時的な失敗は最大3回再試行し、タイムアウト・過負荷が続いても本文リンクを維持します。mei23/summalyは取得先の一時障害も422で返すため、422も再試行対象です。再試行を使い切った失敗はキャッシュせず、再表示時に取得できます。成功結果はブラウザ内で5分、最大256件キャッシュします。

引用RNは通常URLの3件制限とは別に、HomeのDTOに含まれる引用元を専用カードとして表示します。引用先をSummalyに送らず、引用カード内のURLも展開しません。

実行時設定の取得に失敗した場合は、2秒から最大30秒の間隔で取り直します。再試行タイマーもタブ内で共有するため、カードが増えても設定取得の通信数は増えません。最後のカードがアンマウントされたら再試行を停止します。オンライン復帰時も再取得し、タブの再読み込みなしでカード表示を復旧します。成功した設定はタブ内で共有します。

両サービスは [zoo2-infra](https://github.com/Zli-UoA/zoo2-infra) で別々のDeployment・Service・Namespaceとして配備します。運用手順は同リポジトリの `docs/summaly.md` と `docs/media-proxy.md` を参照してください。Rustバックエンドでの独自HTML解析は使用しません。
