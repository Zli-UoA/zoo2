# スレッドの一覧とアーカイブ

参加中のチャンネルの下にスレッドを表示し、活動が7日間ないスレッドを自動でアーカイブします。アーカイブ後も過去の会話を閲覧でき、返信すると自動で再開します。

## 表示と操作

- 削除されていない直接の返信がある投稿を一覧に表示します。返信への返信も独立したスレッドとして扱います。DMは一覧に含めません。
- 名前は親投稿の本文の先頭160文字です。本文が空なら「無題のスレッド」と表示します。独立した名前の設定・変更はできません。
- 親投稿・直接の返信・明示的な再開のうち、最新の活動時刻を保存して並べます。古い履歴を取り込んでも、既存の返信より前の時刻で並べ直しません。
- 一覧のリンクから既存のスレッドペインを開きます。Tabで選択し、Enterで開けます。モバイルではチャット画面へ移動します。
- 一覧は1ページ100件で、「さらに表示」から続きを取得できます。「アーカイブ済みスレッド」を展開すると、そのチャンネルの履歴を取得します。会話の返信は新しい方からページ単位で読み込み、スクロールで古い返信を取得します。再開後も読み込み済みの返信を保持します。
- 投稿権限のあるチャンネル参加者は、履歴を開いてそのまま返信できます。Webでは独立した再開操作を挟まず、返信の保存と同時に再開します。チャンネル自体がアーカイブ済みの場合は返信できません。オフライン時は返信欄を無効にします。
- TUIでは`a`で履歴の表示を切り替え、`/`でチャンネル名・スレッド名を検索します。Enterで開き、`u`で再開します。返信の投稿でも再開できます。アーカイブ中の編集・削除・リアクションはWebと同様に再開後に行います。

## 活動と自動アーカイブ

自動アーカイブまでの期間は全体で7日間です。期間の変更、手動アーカイブ、再開を禁止するロックはありません。

新しい直接の返信と明示的な再開を活動として扱います。閲覧・編集・リアクションは活動に含めません。ワーカーは60秒ごとに最大1,000件を処理し、複数のバックエンド間では行ロックと`SKIP LOCKED`で競合を避けます。

状態は`messages.thread_archive_at`、活動時刻は`messages.thread_activity_at`に保存します。既存のスレッドは移行時に親投稿と最新返信の作成時刻を活動時刻へ反映します。一覧はチャンネルごとの索引からページ件数分を取得し、ワーカーも活動時刻の索引から対象を取得します。返信件数の集計は返すページに限定します。DBトリガーで通常投稿・Home経由の投稿・インポートの返信を同じ経路で扱います。アーカイブ以前の投稿を取り込んでも再開しません。通常の返信が自動アーカイブと重なった場合は再開します。

スレッドのアーカイブは、投稿の削除やチャンネルのアーカイブとは別の状態です。状態だけの更新ではApp向けの`message.updated`イベントを発行しません。通知・未読は既存のチャンネル・返信の処理に従い、スレッド単位の参加・退出や通知設定はありません。

## 権限と同期

`GET /api/threads`は、参加チャンネルのアクティブなスレッドだけを返します。DM・削除済みチャンネル・削除済みの親投稿は含めません。応答は`{items, next_cursor}`形式で、既定・上限とも1ページ100件です。`limit`で件数を減らし、`before`に前の応答の`next_cursor`を渡して続きを取得します。カーソルは活動時刻とIDを保持するため、境界の投稿が削除されても続きを取得できます。`archived=true`で履歴に切り替え、`channel_id`で参加チャンネルを指定できます。応答は`Cache-Control: no-store`です。

`POST /api/threads/{id}/unarchive`はチャンネルへの参加と投稿権限を確認します。閲覧権限がない場合やチャンネルがアーカイブ済みの場合は404、投稿権限がない場合は403です。応答は既存の`data`・`txid`形式で、すでに再開済みなら`txid: null`を返します。

Webの一覧は起動時と60秒ごとに取得し、ウィンドウへの復帰、オンライン復帰、通常投稿・Home経由の返信・編集・削除の保存成功時と、チャンネルへの参加・退出成功時にも更新します。自分の最初の返信によるスレッドの追加と再開は、定期取得やElectricの同期完了を待たず一覧へ反映します。取得中の要求は重複させず、返信の保存前や別ユーザーの取得結果で現在の一覧を上書きしません。他のユーザーの返信による一覧の更新は定期取得で反映します。開いたスレッドの投稿と状態は既存のElectric購読で反映します。定期取得ではアクティブな先頭100件だけを更新します。Webの履歴は展開時に取得し、折りたたみ中と定期取得では通信しません。TUIは起動時・60秒ごと・投稿・編集・削除・再開・参加・退出の完了後に一覧を取得します。`a`で履歴を表示したときに履歴の先頭ページを取得し、一覧末尾の「さらに表示」をEnterで選ぶと次ページを取得します。履歴は定期取得しません。TUIの再開POSTが成功した後の一覧GETが失敗しても、再開失敗とは通知せず、次の更新で再試行します。

マイグレーションはNULL許容の列とトリガー・索引を追加し、旧バックエンドの書き込みにも対応します。検証先は`backend/tests/thread_archive_test.rs`、`frontend/src/hooks/useThreadIndex.test.ts`、`frontend/src/components/chat/ChannelSidebar.browser.test.tsx`、`frontend/src/components/chat/messages/MessagePane.navigation.browser.test.tsx`です。
