# スレッドの一覧とアーカイブ

参加中のチャンネルの下にスレッドを表示し、活動が7日間ないスレッドを自動でアーカイブします。アーカイブ後も過去の会話を閲覧でき、再開すると返信を続けられます。

## 表示と操作

- 削除されていない直接の返信がある投稿を一覧に表示します。返信への返信も独立したスレッドとして扱います。DMは一覧に含めません。
- 名前は親投稿の本文の先頭160文字です。本文が空なら「無題のスレッド」と表示します。独立した名前の設定・変更はできません。
- 一覧のリンクから既存のスレッドペインを開きます。Tabで選択し、Enterで開けます。モバイルではチャット画面へ移動します。
- 「アーカイブ済みスレッド」を展開すると履歴を確認できます。履歴を開くと親投稿の作成時刻まで読み込み範囲を広げ、再開後もその範囲を保ちます。
- 投稿権限のあるチャンネル参加者は、一覧またはペインの「スレッドを再開」で再開できます。チャンネル自体がアーカイブ済みの場合は再開できません。オフライン時は再開ボタンを無効にします。
- TUIでは`a`で履歴の表示を切り替え、`/`でチャンネル名・スレッド名を検索します。Enterで開き、`u`で再開します。返信の投稿でも再開できます。

## 活動と自動アーカイブ

自動アーカイブまでの期間は全体で7日間です。期間の変更、手動アーカイブ、再開を禁止するロックはありません。

新しい直接の返信と明示的な再開を活動として扱います。閲覧・編集・リアクションは活動に含めません。ワーカーは60秒ごとに最大1,000件を処理し、複数のバックエンド間では行ロックと`SKIP LOCKED`で競合を避けます。

状態は`messages.thread_archive_at`、活動時刻は`messages.thread_activity_at`に保存します。既存のスレッドは返信の作成時刻から判定します。DBトリガーで通常投稿・Home経由の投稿・インポートの返信を同じ経路で扱います。アーカイブ以前の投稿を取り込んでも再開しません。通常の返信が自動アーカイブと重なった場合は再開します。

スレッドのアーカイブは、投稿の削除やチャンネルのアーカイブとは別の状態です。状態だけの更新ではApp向けの`message.updated`イベントを発行しません。通知・未読は既存のチャンネル・返信の処理に従い、スレッド単位の参加・退出や通知設定はありません。

## 権限と同期

`GET /api/threads`は、閲覧できる公開チャンネルと参加中の非公開チャンネルのスレッドを返します。ゲストには参加チャンネルだけを返します。DM・削除済みチャンネル・削除済みの親投稿は含めません。応答は`Cache-Control: no-store`です。

`POST /api/threads/{id}/unarchive`はチャンネルへの参加と投稿権限を確認します。閲覧権限がない場合やチャンネルがアーカイブ済みの場合は404、投稿権限がない場合は403です。応答は既存の`data`・`txid`形式で、すでに再開済みなら`txid: null`を返します。

Webの一覧は起動時と60秒ごとに取得し、ウィンドウへの復帰、オンライン復帰、再開操作でも更新します。取得中の要求は重複させず、再開前や別ユーザーの取得結果で現在の一覧を上書きしません。開いたスレッドの投稿と状態は既存のElectric購読で反映します。TUIは起動時・60秒ごと・投稿や再開の完了後に一覧を取得します。

マイグレーションはNULL許容の列とトリガーを追加し、旧バックエンドの書き込みにも対応します。検証先は`backend/tests/thread_archive_test.rs`、`frontend/src/hooks/useThreadIndex.test.ts`、`frontend/src/components/chat/ChannelSidebar.browser.test.tsx`、`frontend/src/components/chat/messages/MessagePane.navigation.browser.test.tsx`です。
