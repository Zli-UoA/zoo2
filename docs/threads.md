# スレッドチャンネルとメッセージ返信

スレッドは親チャンネルの下に作る独立したチャンネルです。各スレッドにはタイトル、投稿、参加者、アーカイブ状態があります。親チャンネルの閲覧権限を持つユーザーはスレッドを閲覧でき、投稿するにはそのスレッドへの参加が必要です。スレッドチャンネルの中に新しいスレッドは作れません。

メッセージへの返信はスレッドとは別の機能です。返信対象は同じチャンネル内（スレッドでは同じスレッド内）の投稿に限り、返信先メッセージIDを`reply_to_message_id`として保存します。所属チャンネルは通常投稿と同じです。返信先へのリンクは投稿と一緒に表示します。新機能では旧方式の`parent_id`による入れ子返信を作りません。段階移行中は、移行前から存在する旧スレッドに限り、旧表示・返信を互換経路で維持します。

## 作成と参加

通常チャンネルのヘッダーからスレッド一覧を開き、タイトルと最初の投稿を入力して作成します。作成者は自動的に参加者になります。親チャンネルにはスレッドへのリンクを含む通知投稿を追加します。スレッド一覧ではアクティブ・アーカイブ済みを切り替え、タイトルを検索できます。

- `GET /api/channels/{parent_id}/threads?archived=false|true&search=...`は親チャンネルのスレッド一覧を返します。検索対象はタイトルです。
- `POST /api/channels/{parent_id}/threads`は`title`と`initial_post`を受け取り、スレッドチャンネル・最初の投稿・親チャンネルの通知投稿を作成します。
- `POST /api/threads/{id}/join`と`DELETE /api/threads/{id}/leave`でスレッド単位の参加・退出を行います。
- スレッドチャンネルは通常の`GET /api/channels/{id}`とメッセージ取得経路から直接閲覧できます。通常チャンネル一覧には表示しません。
- スレッドチャンネルの一般的な名前変更・削除・アーカイブ・チャンネル参加者操作は通常チャンネルAPIでは行えません。アーカイブ操作はスレッドAPIを使います。

## アーカイブ

最後の投稿から1日経過したスレッドは、起動時および60秒ごとのバックエンド処理でアーカイブします。参加者は手動でアーカイブし、再開できます。アーカイブ済み一覧から参加しても、参加状態だけが変わり、アーカイブ状態は維持されます。アーカイブ済みスレッドに投稿すると投稿者が参加者になり、スレッドが再開します。閲覧・参加だけでは再開しません。

- `POST /api/threads/{id}/archive`でアーカイブします。
- `POST /api/threads/{id}/open`で再開します。

アーカイブ状態と最終活動時刻は`threads.archived_at`と`threads.activity_at`に保存し、`channels.thread_archived_at`と`channels.thread_activity_at`へ同期します。ワーカーは1回につき最大1,000件を処理し、複数バックエンド間の競合を行ロックと`SKIP LOCKED`で避けます。通常投稿・Home経由の投稿・インポートもDBトリガーを通じて活動と再開に反映します。

## 既存データの移行

移行は段階的に行います。第1段階ではスキーマを追加し、旧返信を親チャンネルに残します。旧スレッドは従来の表示と返信を維持し、互換用の`legacy_thread_roots`に記録した既存スレッドだけ旧書き込みを許可します。第2段階は第1段階のバックエンドが稼働した後に適用し、旧返信を新しいスレッドチャンネルへ移します。親投稿は親チャンネルに残し、返信の投稿ID・本文・投稿者・投稿日時を維持します。移行前の返信先IDは`reply_to_message_id`に保持し、返信先へのリンクをたどれるようにします。スレッド名には親投稿本文の先頭100文字を使い、スレッド通知を親チャンネルへ追加します。移行時点で1日以上活動のない旧スレッドはアーカイブします。

移行後の新規返信は、チャンネル内または同じスレッドチャンネル内の投稿を返信先に指定できます。スレッド所属先と返信先は別々に保存されます。削除済みの返信先は別の投稿へ置き換えず、利用可能な返信先情報を表示します。

## 旧メッセージスレッド API

旧方式のメッセージスレッドは、段階移行が終わるまで既存リンク・Webの返信ペイン・TUIの一覧から閲覧できます。`GET /api/threads`は新しいスレッドチャンネルと旧メッセージスレッドをクライアント互換のため同じ形式で返します。新しいスレッド作成・管理画面はチャンネル単位の`/api/channels/{parent_id}/threads`を使います。
