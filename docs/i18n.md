# 翻訳辞書と x18n による検査

Web 版の文言は `frontend/src/lib/i18n/locales/*.json` にまとめ、日本語（`ja.json`）を基準にしています。Android 版もビルド時に同じ JSON を assets へ取り込むため、辞書を変更するときは両方への影響を確認してください。

## 検査

`x18n` は参照側のキーの存在、他ロケールのキー欠落、プレースホルダの不整合、未使用キー、動的キーを検査します。辞書同士のキー一致は `locale.test.ts` でも検査しており、x18n と二重に担保します。

```sh
pnpm --dir frontend check:i18n          # CI と同じ検査
pnpm --dir frontend exec x18n doctor     # 検出された辞書・スキャナの確認
pnpm --dir frontend exec x18n usages <key>
```

設定は `frontend/x18n.config.ts` にあります。CI では `ci-frontend.yaml` の `check` ジョブから実行します。frontend の変更を含む PR では実行され、proxy・frontend コンテナ・backend のテストだけの PR では省かれます。

## 動的キー

`dynamic-key` はエラーにしてあり、`t(key)` のような静的な前方一致がない呼び出しは CI で落ちます。キーは次のどちらかの形で書いてください。

```ts
// 静的な前方一致 + 型付きの接尾辞（推奨）
const ERROR_SUFFIXES = {
  denied: "denied",
  failed: "failed",
} as const;

declare const reason: string; // URL や API 由来の文字列
const suffix = Object.hasOwn(ERROR_SUFFIXES, reason)
  ? ERROR_SUFFIXES[reason as keyof typeof ERROR_SUFFIXES]
  : ERROR_SUFFIXES.failed;
t(`slackLink.errors.${suffix}`);

// 取りうるキーが少ない場合は分岐にする
t(kind === "mfm" ? "mfm.suggestions" : "mentions.suggestions");
```

前方一致のあるテンプレートは x18n が「その接頭辞の下のキーをすべて使う可能性がある」と扱うため、`missing-key` / `unused-key` の誤検知を避けられます。接尾辞側は `as const` のリテラル型にしておくと、i18next の型付きキーによって実在するキーかどうかも TypeScript が確認します。接頭辞の下のキーはすべて「使用中」になるので、新しいキーを足しても `unused-key` では報告されない点に注意してください。

`@x18n-key` と `@x18n-keys` は文字列や配列・オブジェクトを「使用中のキー」としてマークしますが、`dynamic-key` のエラー自体は消しません。やむを得ず変数のまま呼ぶ場合は、その呼び出しをリテラル分岐か前方一致テンプレートへ直す方針にしてください。

## 未使用キーと Android

x18n は frontend のソースだけをスキャンします。Kotlin 側だけで使われるキー（例: `androidPhone.*`）は `unused-key` の警告として表示されます。これは警告どまりで CI は失敗しませんが、**この警告を根拠に `x18n delete --unused` を実行しないでください**。Android が同じ辞書を読んでいます。

## 書き込みコマンド

`x18n set` / `apply` / `fill` / `rename` / `delete` / `extract` は辞書を書き換えます。Android が同じ JSON を読むため、これらの変更は内容をレビューしてからコミットしてください。CI は読み取り専用の `x18n check` だけを実行します。

共有辞書の補間変数は `{{name}}` の形で記述します。Android はこのトークンを完全一致で置換するため、空白やフォーマッターを含む `{{ name }}` や `{{name, fmt}}` は辞書検査でエラーになります。
