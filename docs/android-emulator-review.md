# Android エミュレーターでのデザイン照合

[UI デザインサンプル](android-design-samples.md) と、Android Emulator の AOSP API 35、Pixel 6 相当、縦向き 400dp、標準文字サイズで照合した。画面は ADB のスクリーンキャプチャ。KVM が利用できないホストでソフトウェア CPU エミュレーションを使用し、初回起動時は Android のシステム UI とアプリに応答待ちが発生した。速度や遷移時間の評価は対象外とする。

ログイン画面は通常の Debug APK。ログイン後の確認用 APK では、同じ Compose 画面とルーティングに架空の投稿・会話・通知などを渡した。認証、実サービスとの通信、Telecom・通話音声は確認用データの範囲外。

中央の Zoo マーク、ブラウザ認証の案内、内容幅のボタンを確認した。通常の Debug APK には Android 用 public client ID の初期値がなく、接続先設定が最初から展開され、ログインボタンが無効だった。モックでは初回からログインボタンを押せる。更新バーが追加され、ダークでも OS の上下の帯が明るく残った。ブラウザに遷移して認証を完了し、App Links 経由で復帰するところは確認できていない。

## アプリ内で確認した画面

| 画面 | エミュレーターのキャプチャ | 照合結果 |
| --- | --- | --- |
| チャンネル一覧 | [ライト](images/android-design/emulator/channel-index-light.png) | 名前だけの1行、区切り線なし、検索・参加中・DMの順、5タブを確認。 |
| チャンネルの会話 | [ライト](images/android-design/emulator/conversation-light.png) | チャンネル説明の1行省略、本文面の地色、タブなし、入力欄の上端のつまみを確認。見本の入力中・全画面状態との照合は別途必要。 |
| DM 作成 | [ライト](images/android-design/emulator/dm-create-light.png) | 検索と選択欄を起動。子画面のためタブは表示されない。 |

ソフトウェアエミュレーションでは、画面遷移の直後に前の画面がキャプチャされることがあった。表には画面内容を確認できたキャプチャを掲載する。残るトップ・子画面と、呼び出し、OS 通知、写真の権限や選択、キーボード、TalkBack の照合は完了していない。

## 残る画面の確認項目

| 範囲 | 確認に必要な状態と照合箇所 |
| --- | --- |
| ホーム・投稿詳細・プロフィール | 本文の余白と地色、長押し、投稿詳細からの復帰、プロフィールと検索の画面遷移 |
| 投稿作成と添付 | 下書き、最近の写真、アクセス許可、OS の写真ピッカー、添付後のプレビュー |
| チャンネルの子画面 | 検索、作成、設定、メンバー管理、権限別の表示。会話では IME、全画面入力、左スワイプ、スレッドとの往復 |
| 通知・Bubble | 通知の種類とフィルター、画像付き通知、通知シェードからの操作、Bubble の入力と表示 |
| 設定の子画面 | 外観、一般、通知、更新、連携、暗号化、鍵が未保存のときのログアウト確認 |
| 通話 | 着信・通話中・終了とライト／ダーク。OS 着信通知と画面遷移も確認する |
| Android の端末操作 | 文字拡大、TalkBack、戻る、動きを減らす設定。入力や遷移の追従はソフトウェアエミュレーションの起動時の負荷と分けて確認する |
