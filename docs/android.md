# Android 版

Android 8.0（API 26）以降を対象にした Compose Multiplatform クライアントです。
このプロジェクトの Compose for Android に廃止予定はなく、開発・検証・配布を継続します。
実験を終了したのは Compose for Web のみです。`frontend-compose/` 全体や、Android が利用する共有 Kotlin コードは廃止対象ではありません。
共通 Kotlin の `frontend-compose/src/commonMain` にある `ZooApp`、画面・部品、
`Session`、`Repository`、REST API、Electric4k の同期処理をそのまま使います。
Android 用に別のチャット画面や同期クライアントは持ちません。

## ビルド

JDK 21、Android SDK Platform 35・36、Build Tools 35.0.0、Node.js 24とリポジトリ指定のpnpmを用意してください。
初回は `pnpm --dir frontend install --frozen-lockfile` を実行します。
Android Studio で `frontend-compose` を開き、Gradle プロパティに
`zoo.android=true` を設定するか、コマンドで指定します。
`nix develop .#android` は CI と同じ Android 35・36 / Build Tools 35.0.0 と NDK を含め、
`ANDROID_HOME`・`ANDROID_NDK_HOME` を設定します。
SDK の場所は `ANDROID_HOME` または Git 管理外の `local.properties` で指定します。

```sh
cd frontend-compose
./gradlew -Pzoo.android=true :androidApp:assembleDebug
./gradlew -Pzoo.android=true :androidApp:testDebugUnitTest testDebugUnitTest :androidApp:lintDebug
adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

Android ターゲットは `zoo.android=true` で明示的に有効にします。
フォントはチェックサムを固定して取得・生成し、翻訳辞書は
`frontend/src/lib/i18n/locales` からビルド時に APK の assets へ取り込みます。
CI Android はビルド・テスト・lint を実行し、debug APK を artifact に保存します。

## SIP・DM通話とAndroid Telecom

「設定 → 通話 → 電話（SIP）」で個人用・共有用の回線、利用メンバー、電話機の連絡先を登録・編集できます。共有回線の管理は管理者、利用は明示したメンバーのみです。個人回線は本人だけが利用します。PBX・TURN・VPNの構成は [SIP電話](sip.md) を参照してください。

DMヘッダーの通話ボタンは既存の通話SSEとWebRTCへ接続します。DM着信を受ける場合は、設定で「DMの着信を受ける」を有効にします。招待のShapeはセッション全体で1本、永続キャッシュなしで購読します。回線一覧は設定表示・手動更新・変更後に取得し、ポーリングしません。回線一覧の取得、接続、保存や削除に失敗した場合は、電話（SIP）画面にエラーを表示します。DMの待受を有効にできなかった場合は、設定の通話欄にエラーを表示します。通話SSEは通話中だけ1本、既存APIへの heartbeat は初期の通話状態を受信してから10秒後に送信し、その後は直前に成功したリクエストの送信時刻から10秒後を目安に送信し、終了・ログアウト時に停止します。初回の応答は最大15秒待ちます。一時的な失敗では1秒空けて最大2回再試行し、再試行1回の待機は最大5秒です。応答待ちと再試行は、在席期限の30秒に余裕を持たせるため、直前に成功したリクエストの送信時刻から29秒以内に収めます。初回は初期の通話状態を受信した時刻を使います。408・429を除く4xxや再試行の上限に達した場合は通話を終了します。開始前のイベントは最大128件を初期状態まで保留します。発信後や着信への応答後、45秒以内に音声が接続しなければ通話を終了します。

両方の通話をAndroid Telecomのself-managed `ConnectionService`へ登録します。着信・発信の管理、ヘッドセットからの応答・終了、OSからのミュート・音声経路変更をアプリの通話へ渡します。Android 12以降ではCallStyle通知を使います。端末が着信時のCallStyleを受け付けない場合や古いAndroidでは、応答・終了ボタン付きの通知を表示します。ロック画面の着信には、アプリ内と共通の着信画面を使います。通話中はミュートとスピーカーを切り替えられます。SIPのDTMFはTelecomから受け取ります。通話画面を最小化すると、アプリの上部に通話状態と「通話を開く」ボタンが表示されます。接続済みの通話では、対応端末の「通話を小窓で表示」ボタンでAndroidのピクチャーインピクチャー（PiP）を開けます。PiPには取得できた相手のアバターを表示し、画像がなければDMでは名前の頭文字、SIPではZooマークを表示します。小窓を閉じても通話は続きます。切断は小窓の操作または通話通知から行えます。既定の電話アプリへの変更、通話履歴への書き込み、保留・転送は行いません。同時に扱う通話はSIP・DMを合わせて1つです。

DMの発信中は、Zooが `ToneGenerator` を使い、端末の通話音量で呼び出し音を再生します。相手の応答・拒否で招待がなくなるか、接続・終了すると止まります。招待を同期できない場合も、再生は最長30秒です。自己管理通話でTelecomに呼び出し音を要求するとAndroid 15エミュレーターで例外が発生したため、Zooが再生を管理します。SIP発信ではZooの呼び出し音を重ねず、PBX側の音声に従います。

音声はDM・電話共通のWebRTC、呼制御はComposeが所有する認証済みHTTP/SSEです。専用WebViewにはAPK同梱の音声エンジンだけを読み込み、SIP.js・SIP認証情報・APIトークンを渡しません。音声エンジンは `pnpm build:android-phone` で生成します。外部ページ・遷移・ファイルアクセス・追加のfetch/WSSを拒否します。マイクはAndroidの許可とTelecomによる通話の受け入れ後に限って許可し、カメラは許可しません。

待ち受け中の常駐通知はありません。SIPはゲートウェイのイベントストリーム、DMは通話招待のShapeで待ち受けます。FCMを設定した配布物では、通知を許可してDM着信を有効にすると、アプリを閉じていてもDM着信通知を受け取れます。通知から応答すると、ログインを復元し、招待の同期で対象の通話を確認してから接続します。設定からアプリを強制停止した場合は、手動で起動するまで着信通知を受け取れません。Telecomが着信を許可すると応答・拒否付きの通知を表示します。着信チャンネルは優先度「高」とバイブを使い、呼び出し中は通話通知を表示します。Androidで全画面の着信通知が許可されている場合は、画面消灯中に点灯して通話操作と、分かる範囲の相手の名前・アイコンをロック画面に表示します。同期前のDM着信でアイコンが取得できない場合は頭文字を表示します。全画面表示は、応答前に相手を確認できるよう、通常の通知プレビューを非表示にしていても発信者を表示します。通知一覧の公開表示は着信の文言のみです。全画面通知が許可されない場合の着信表示はAndroidが決めます。同期前のDM着信通知を「閉じる」とその端末だけで通知が消えます。Android 14以降の全画面通知は「設定 → 通話 → 着信時の全画面表示を設定」から許可できます。通知の優先度やバイブは端末の通知設定とサイレントモードに従います。発信の許可後または着信の応答時に、通話・マイク用のフォアグラウンドサービスを開始し、通話終了時に停止します。通知からの応答はアプリの画面を開きます。通知操作はセッションと通話IDで検証し、ログアウト・アカウント切替で待ち受けと通話を終了します。

SIPと、FCM未設定の端末でDMの着信を待つ間はZooを前面に開いてください。画面を閉じたり別のアプリに切り替えたりすると、DozeやApp Standbyによるネットワーク制限、キャッシュ済みアプリの凍結により、プロセスが残っていても待ち受け接続が途切れることがあります。待ち受けに必要な接続はSIPの回線登録とDMの招待同期です。SIPでプロセス終了後や再起動後にも着信を届けるには、PBX側で着信を保持して端末へのPush配送を起動する経路が必要です。着信の表示には通知の許可、通話にはマイクの許可と最新のAndroid System WebViewが必要です。

共通Kotlinテストで権限再確認・期限切れ・応答中の同期競合・遅延応答・通話の排他を、Robolectric（API 28/35）でTelecomコールバックとWebViewのオリジン制限を検証します。Chromiumでは実際のaudio-only SDP交渉とマイク解放を検証します。実機のBluetooth・有線ヘッドセット・ロック画面・通常電話との競合・バックグラウンド着信・TURN越しの音声とDTMFは、PBXを用意した端末で確認してください。

## 安定性と端末での確認

### 画面と操作

幅768dp未満では、Home・チャンネル・通知・Bubble Chat・設定をラベル付きの下部ナビゲーションに配置します。
キーボード表示中、スレッドとメンバーの専用画面ではナビゲーションを隠し、入力・返信の領域を確保します。
768dp以上では既存の左ナビゲーションを使い、1024dp以上ではメンバー・スレッドの並列表示を維持します。
通知数は既存の共有状態から取り、ナビゲーション用の追加取得は行いません。

[Android のデザイン規則](android-design.md) と [UI デザインサンプル](android-design-samples.md) を参照してください。

Androidの本文は17sp/25sp、補助テキストは14spを基準とし、共通ボタン・入力欄・選択欄・メニューは48dp以上、
チャンネル・DMの一覧行は48dp以上の高さを確保し、行間の余白は設けません。
ヘッダーは56dpを基準とし、通知・Home・チャットは40dpアバターと本文間12dpを基準とし、Homeの投稿は左右・上下12dp、チャンネル入力欄の背景を画面端まで広げ、操作列は左右と下から4dp内側に置きます。ヘッダーとボタンは文字倍率に合わせて高さを広げられます。
設定の説明と操作は配置幅480dp未満で上下に並べます。入力・IME変換・下書き保存は既存の共通処理を使います。
チャンネル入力は上端のつまみを上へスワイプすると全画面へ展開します。展開ボタンは置かず、戻る・つまみの下スワイプで縮めます。選択範囲と添付を保持し、Aaから既存のMFM書式を挿入できます。
操作アイコンの表示は24dp、背景は32dpを基準とし、透明な周囲を含む操作領域は48dp以上にします。
Homeの本文の下書きはセッション内で保持し、別画面との往復で失わないようにします。他のアカウントとは共有しません。
設定にログアウト操作を置き、Androidで利用できないPWA通知設定は表示しません。最上位での戻る操作ではタスクを背景へ移します。
参加済みの通常チャンネルではオフライン中も本文の下書きを入力でき、送信・添付の追加は通信復帰まで無効にします。
未参加・アーカイブ済みチャンネルの投稿制約は維持します。
暗号化チャンネル・DM は解錠済み端末から本文・返信・編集・添付を送信でき、復号した本文と添付は同期キャッシュへ保存しません。
暗号化チャンネルの添付は端末で暗号化してから上げ、受け取った添付はタップで復号して端末の共有で開きます。詳細は [E2EE](e2ee.md#compose-android) を参照してください。

Homeから個別投稿を開くときは、タップ時点の投稿DTOをSession内で渡し、スレッド取得を待たずに本文を表示します。本文・日時・取得済みの返信先リンクを対象とし、返信や最新の情報は既存のスレッド取得で更新します。通信失敗時は本文を残し、403・404では本文と関連キャッシュを取り除きます。受け渡しは一度だけで、別アカウントとは共有しません。

Homeのタイムライン選択には横スクロール可能なタブ、更新にはMaterialのPullToRefreshBoxを使います。手動更新・タブ切替では先頭へ戻し、末尾10項目に近づくと50件ずつ追加取得します。
手動更新だけ進行状態を表示し、取得失敗時には既存の投稿を残します。共有の更新集約処理で先頭50件と表示中の範囲だけを再確認し、読み込み済み履歴を全件取り直しません。
読み込み中・空・取得失敗には共通表示を使い、取得失敗には再試行操作を用意します。
オフライン通知は本文に重ねず、画面内で領域を確保します。
共通部品のラベル・選択・役割・状態通知をAndroidのアクセシビリティツリーにも渡します。

`testDebugUnitTest` はRobolectricのCompose UIテストも実行します。
320dpと600dpのナビゲーション、明暗テーマ、文字倍率180%での日本語入力、タッチ領域と無効状態、
エラーからの再試行を検査します。キャプチャは `frontend-compose/build/reports/ui/` に保存し、
CIの `zoo-android-test-reports` artifactにテストレポートと一緒に収録します。
キャプチャは確認用で、自動の画像差分判定や実機のTalkBack検証ではありません。

### MFM 本文

本文の解析は `MfmParser.kt`、関数の引数・変形・アニメーションの設定は `MfmFunctions.kt` にまとめます。
コード・`<plain>`・数式内のリテラルと、関数・装飾タグ・リンクの入れ子を区別します。
再帰の深さに加えて解析全体の走査回数も制限し、上限に達した残りは原文のまま表示します。
CRLF・CRの入力は見出し解析前に改行を正規化します。
リンクラベル内の装飾本文にも外側リンクのタップ領域を配置し、内部のクリック関数は抑制します。
ルビは装飾や関数内の空白を親文字の一部として扱い、読みを親文字の上に半分の文字サイズで配置します。
関数には親の太字・色・文字サイズを引き継ぎ、長い本文は配置先の幅で折り返します。
`<plain>` は通常の本文として折り返し、装飾やリンク化をしません。

ぼかしはタップで切り替え、フォーカス・ホバーでも解除します。拡大は縦横比を維持して累積8倍までに制限し、
縮小で上限を緩めません。位置指定は現在の文字サイズに連動し、変形が本文の外へはみ出す部分は切り取ります。
動きを減らす設定ではアニメーションを停止します。速度・遅延は `s` / `ms` 単位を必要とし、
非有限の値や不正な引数には既定値を使います。未知の関数・不正な日時は元の記法を表示します。

数式はAndroidのネイティブ描画で、分数・添字・平方根・行列・定義済み記号などに対応します。
KaTeXの全機能を実装するものではありません。未対応コマンドや括弧・引数が不足する式は元の式を表示します。

| 検証対象 | テスト |
| --- | --- |
| 入れ子・コード・plain・エスケープ・リンク・不完全な入力 | `MfmParserTest`、`ContentTest` |
| 見出しと装飾・ブロックとの境界 | `MessageHeadingsTest`、`MfmParserTest` |
| 対応24関数・引数・色・縦横比・上限・ルビ・動きの抑制 | `MfmFunctionsTest` |
| 数式の構造・不正な式・未対応コマンド・深い入れ子 | `MathParserTest` |
| 実際の本文・全関数・ルビの配置・装飾継承・枠線・フォント・タップ・動くフレーム | `MfmUiTest`（Robolectric / API 35） |
| 320/600dp、文字倍率180%、明暗テーマ、長い日本語の折り返し | `MfmUiTest` |

Android CIの `zoo-android-test-reports` artifactにテスト結果と `mfm-*.png` のキャプチャを保存します。
この修正はAndroidの解析・描画に固有のもので、React・TUI・デスクトップの解析器は変更しません。
通信経路とAPIは変更しません。実機上のTalkBack・IMEや全Androidバージョンでの確認を代替するものではありません。

### 画像・保存・接続

画像プレビューは受信中に20 MiBの上限を確認し、Content-Lengthがない応答にも適用します。
デコード前に縦横それぞれ2048px以内になるよう縮小し、EXIFの回転・反転を維持します。
アバター・リンクプレビュー画像・サイトアイコンも `Session.imageBitmap` から端末の共通デコーダーを通します。
デコード済み画像を最大64MiB・256件まで共有LRUキャッシュし、一覧へ戻るたびの再デコードも省きます。
これはプレビューの制限で、添付ファイルのアップロード上限（50 MiB）は変更しません。
大きすぎる画像は既存の画像取得失敗表示になります。

同期キャッシュはアカウントごとに原子的に置き換え、読み書きとログアウト時の削除を直列化します。
チャンネルのメッセージは、直近50件ずつ subset snapshot で取り、画面の先頭に来たときに古い50件を足します。同期キャッシュに残すのは各チャンネルの最新50件だけです。詳細は [オフライン閲覧とメッセージの範囲](offline-windowed-messages.md#androidcompose) を参照してください。
ログアウト後に届く古いセッションの書き込みではキャッシュを作り直しません。
Androidの戻る履歴には各画面の状態と位置を保存し、メンバー画面から戻る際に前の画面の状態を復元します。
同じパスへの連続移動では戻る手順を増やしません。Homeの投稿と位置もセッション内に最大8画面（各1,000件・4MiB）保持し、直近の先頭確認から30秒以内の往復では再利用します。

ネットワークは既定の接続にINTERNETがある場合に通信可能な候補として扱います。
学内・社内回線など、Androidの外部接続確認だけが遮断される環境でも使えるよう、VALIDATEDは必須にしません。
VALIDATEDの変化だけではオンライン/オフラインを切り替えず、再取得も起動しません。
Zooへの到達や認証の失敗は、既存のHTTP・同期処理のエラーとして表示します。到達確認用の追加通信は行いません。
可視状態はセッション開始時とActivityのライフサイクルから渡し、破棄済みの購読からの遅延通知を無視します。
通信の再許可でオンラインに戻ったとき、またはオンラインのまま既定の回線が切り替わったときは、HTTPの接続プールを更新し、共有ShapeとHomeのWebSocketを再接続します。
通信制限の変更通知がないAndroid 8・9や、通知の時点で既定回線をまだ取得できない場合に備え、画面が表示中でオフラインの間だけ、2秒から最大10秒の間隔でOSの接続状態を再確認します。この確認ではZooにリクエストを送りません。

Homeの送信はSessionのスコープで実行し、画面を離れても応答を待ちます。
送信中のアップロード済み添付は画面の破棄で削除せず、成功後に本文の下書きと端末側の参照を片付けます。
送信失敗時は本文を残し、画面を既に離れている場合は未使用の添付を破棄します。

PRの単体テストに加えて、配布前に次を端末で確認します。

- Auth Tab 対応と非対応のブラウザーで、ログイン・キャンセル・復元・ログアウトを行う。API 26 と 35 で起動を確認する。
- ホーム→チャンネル→メンバー→戻る、同じ画面の再選択、ワイド画面への回転で履歴を確認する。
- Wi-Fi切断・キャプティブポータル・通信復帰、バックグラウンドと復帰時の表示と取得回数を確認する。
- 大きな縦長・横長画像、EXIFの回転画像、壊れた画像、20 MiBを超える応答でアプリが操作可能なことを確認する。
- 書き込み中のプロセス終了と再起動、ログアウト直後の再ログインでキャッシュが混ざらないことを確認する。
- 小さい画面・大きい文字・明暗テーマ・TalkBackでログイン入力とエラー通知を確認する。

起動時間・スクロールのフレーム時間・メモリ使用量の性能保証には、実機での計測が別途必要です。
単体テストの成功だけで、これらの性能や端末上の表示品質を保証したとは扱いません。

## ログイン

初回ログインと暗号化の再認証には OIDC 認可コードフローと S256 PKCE を使います。対応ブラウザーでは Auth Tab を開き、Digital Asset Links で検証された HTTPS リダイレクトをブラウザーの結果として受け取ります。Auth Tab 非対応時は Custom Tabs と検証済み App Links を使います。コールバックの `state` とIDトークンの `nonce` を照合してからセッションを作ります。初回ログインは `offline_access` を要求し、暗号化の再認証は `max_age=0` を指定します。

「接続先の設定」でZooサーバーのHTTPS origin、OIDC issuer、Android用public client ID、resourceを設定できます。既定のサーバーは `https://zli.chat`、issuerは `https://account.zli.works/api/auth`、resourceは `https://zli.chat/api` です。初回にclient IDを設定してください。

認証サービスにはAndroid用public clientの認可コードグラントと、本番の戻り先 `https://zli.chat/android/reauth-callback` を登録します。別のビルドでは設定された App Links ホストを使います。`openid profile offline_access` と対象APIへのアクセスを許可します。

初回はブラウザーで認証します。以後はアプリの再起動時に保存した refresh token で
アクセストークンを取得し、同じ接続先へ自動でログインします。更新時に refresh token が
ローテーションした場合も保存し直します。refresh token が発行されないクライアントでは、
従来どおり起動ごとのログインが必要です。

アクセストークンはメモリだけで保持し、有効期限の60秒前から更新します。
refresh token と元の接続設定は、Android Keystore の AES-256-GCM 鍵で暗号化して
private preferences に保存します。平文のトークンは保存せず、バックアップ・端末間転送も無効です。
接続先・issuer・client・Resource は暗号化した同じレコードから復元し、変更した接続先へ
以前のトークンを転送しません。Keystore の鍵が利用できなくなった場合や、トークンが失効した場合は
手動ログインへ戻ります。

認証先の設定取得や DNS・TCP 接続・接続タイムアウトなど、更新リクエストの送信前に通信障害が起きた場合は保存情報を残し、
「自動ログインを再試行」や通信復旧後の更新で復帰できます。OkHttp の自動再送とリダイレクトを無効にし、
送信前の接続失敗と確認できる場合だけ、取り除いた refresh token を保存し直します。保存し直せない場合や
その間にログアウトした場合は復元しません。送信前には古い refresh token を保存領域から取り除き、
取り消しが要求されても、交換結果を受け取って保存するまで待ちます。送信後にタイムアウト・応答喪失・
不正な応答・保存失敗が起きた場合は、古い token を再送せず手動ログインへ戻ります。
AuthZ は使用済み token の再利用を検知すると同じ client・ユーザーの refresh token をすべて失効させるため、
送信後の失敗を単純に再試行することはできません。

復元の待機中も「ログイン画面を開く」で中止を要求できます。交換中の場合は、HTTPタイムアウトを上限に
交換と保存が終わるまで待ってからログイン画面へ戻ります。後から始めた別のログインの保存情報を、
古い処理が上書き・削除することも防ぎます。接続設定を変更して手動ログインを始めると、
以前の保存情報を削除します。ログアウトは保存した認証情報・暗号化鍵・ローカルセッション・
アカウント別の同期キャッシュを削除します。ログアウト後に遅れて届いた更新応答は保存しません。
IdP 全体のブラウザーセッションや他端末の認証は失効させません。
接続設定とアカウント別の下書きは、従来どおりアプリの private preferences に保存します。

## エンドツーエンド暗号化（E2EE）

ログインすると、裏で E2EE の端末を登録し、鍵を補充して、自分の端末あての to-device メッセージ
（Megolm のセッション鍵）を受け取ります（[#359](https://github.com/Zli-UoA/zoo2/issues/359)）。
暗号の処理は zoo-crypto の UniFFI バインディング（`crates/zoo-crypto-ffi`）で行います。
暗号ストアは接続先とユーザーごとに `noBackupFilesDir/e2ee/` に置き、保存鍵は Android Keystore の鍵で包みます。
自動バックアップと端末間の転送には入りません。失敗は表示せず、間隔をあけて試し直します。

ログアウトでは、鍵バックアップに送れていない鍵があれば件数を示して確かめ、暗号ストアを消してから
サーバーの端末を削除します。オフラインなどで削除できなかった端末は、同じユーザーの次のログインで消し直します。
設定の「暗号化」タブで、初回設定と、パスキーかリカバリーキーでの解錠を行います（[#360](https://github.com/Zli-UoA/zoo2/issues/360)）。
初回設定では、リカバリーキーを控えたあと、保存の直前に Auth Tab（非対応時は Custom Tabs）でログインし直します（再認証）。
ログインが終わると Auth Tab の結果、または App Links が `https://zli.chat/android/reauth-callback` をアプリに渡し、同じ画面のまま保存します。
Auth Tab と App Links の検証には、zli.chat の nginx が配る `/.well-known/assetlinks.json` が要ります。
frontend のコンテナの `ANDROID_APP_CERT_SHA256` に、配布する APK の署名証明書の SHA-256 の指紋を入れてください
（zoo2-infra。debug APK は署名が違うので、App Links で戻りません）。
AuthZ の Android のクライアントには、認可コードのグラントと、このリダイレクト URI の登録が要ります。
backend は再認証の ID トークンの `aud` を `OIDC_REAUTH_AUDIENCES`（カンマ区切り）で確かめます。この値は zoo2-infra の
production の `backend.yaml` の `env` にあり、Android の client ID（`129d96c7c57d46729fe5ee31ff95e7fc`）は入っています
（[E2EE の「有効化と運用」](e2ee.md#有効化と運用)）。Android の client ID を変えるときは、この一覧も zoo2-infra の PR で直してください。
リダイレクト先のホストはビルド時の `-Pzoo.android.reauthHost=<ホスト>`（既定は `zli.chat`）で、manifest の App Links と
認可リクエストの両方に使います。接続先のサーバーが違っても、このホストに戻ります。
パスキーは Credential Manager の PRF で使いますが、AuthZ の `assetlinks.json`（AuthZ#96）が要り、実機ではまだ確かめていません。
使えないときは、リカバリーキーで解錠してください。解錠した端末だけが、受け取った鍵を鍵バックアップに送ります。
設定の「暗号化」で、端末の一覧と削除、端末と鍵の失効（再認証を通す）、他のユーザーの絵文字と QR コードでの検証（QR はカメラで読み取る）を行えます（#362）。
暗号化チャンネルの Push 通知は、端末の暗号ストアで復号して本文を出します（#510。復号できなければ「新しいメッセージ」）。
サーバーには平文を渡しません（[E2EE の「Android の Push の復号」](e2ee.md#android-の-push-の復号510)）。
詳細は [E2EE の「初回設定と解錠の実装」](e2ee.md#compose-android)と[「暗号ストア」](e2ee.md#暗号ストア)を参照してください。

## Android との接続

- `androidApp` は起動、デバイス認証、ナビゲーション履歴、外部ブラウザー、クリップボード、
  ファイル選択と署名付き URL へのアップロード、翻訳、アカウント別キャッシュを接続します。
- `src/androidMain` は文字照合、テキストスタイル、Home の WebSocket の実装です。
- 戻る操作はオーバーレイ、スレッド、画面履歴の順に閉じます。
- システムバーと IME の領域を避け、テーマと表示状態を共有セッションへ渡します。
- 公開画像・URL プレビュー・署名付き添付 URL には Zoo の認証ヘッダーを送りません。
- Android の通知権限を許可すると、ログイン中に同期した新着のチャンネル通知を、表示中・非表示のどちらでも表示します。
  Android 13以降はログイン後に一度だけ通知権限を要求し、拒否した場合は既存の有効化ボタンから再設定します。
  メンション・DM・リアクションを別チャンネルにし、通知から対象投稿へ移動、既読化、直接返信できます。
  メンション・DM・返信は Android 標準の会話形式で表示し、送信者のアバターは外部画像用のプロキシと、登録ごとのPush専用ディスクキャッシュを使って補います。Push登録の解除時に該当キャッシュを削除します。
  画像を待たずに本文を通知し、画像の失敗・8秒の期限超過では画像なしの表示を維持します。
  アバター取得は同じURLで共有し、デコードは同時2件、保持するサムネイルは最大64件に制限します。
  取得の並列数はデコード用の制限と分け、失敗・期限超過した画像は次の通知更新で再試行できます。
  グループ概要は一括更新ごとに1回だけ更新し、アバターの反映時には概要を再投稿しません。
  同じチャンネル・通知種別の系統（メンションと返信／DM／リアクション）に2件以上ある場合は、
  Android のグループ表示で束ね、概要に直近5件を表示します。個々の既読・返信操作は維持します。
  グループをスワイプするとそのグループだけを端末上から取り消し、サーバー側の既読状態は変えません。
  リアクションは反応した人・絵文字・対象投稿の本文を表示します。添付画像のプレビューは未対応です。
  直接返信は、同期済みの最新50件に対象とスレッドのルートがある場合だけ有効です。
  未同期のチャンネルや削除済みの対象は通知から画面を開いて確認します。通知ごとの追加購読は作りません。
  初回同期の過去通知と同一IDの再配信は通知せず、既読・削除・ログアウトで通知を取り消します。
  公開画像は認証ヘッダーを付けずにHTTPSのCDNリダイレクトを追い、HTTPへの降格・循環は拒否します。
  ロック画面では内容を隠し、返信・既読アクションは通知を作成したセッションだけで処理します。
  返信の送信後に既読化だけが失敗した場合は、返信ボタンを外して既読操作だけを再試行します。
  9秒の期限超過でも現在表示中の通知を更新し、取消し済み通知はエラーで再表示しません。
  応答を受け取れなかった返信は通知IDと送信本文の組でIDを保持し、同じ本文の再送だけで再利用します。
  本文を変えた場合は新しい投稿として送信します。期限超過した古い本文も保存済みだった場合は両方が残り、
  古い投稿を上書き・削除しません。平文APIは同一ID・異なる本文を競合として扱います（暗号化チャンネルへの直接返信は無効です）。
- Firebaseを設定した配布物では、既存の通知作成後にFCM HTTP v1でdataメッセージを送り、
  `FirebaseMessagingService`で表示中・バックグラウンド・通常のプロセス終了後も受信します。
  同期とFCMは利用者ID・通知IDから同じ通知タグを作ります。先に表示された同期通知の返信操作などを、遅れて届いたFCMで上書きしません。
  FCM の通知は会話形式で表示し、送信者アバターと、すでに公開されている添付画像を取得できた場合に表示を更新します。本文は先に出し、画像取得は最大3秒で打ち切ります。
  添付のプレビュー対象は、公開チャンネルからホームに公開済みの4MiB以下の非センシティブ画像です。DM、非公開・暗号化・センシティブ設定のチャンネル、リアクションの添付は対象外です。
  通知を開くとログインを復元してから対象投稿へ移動します。ログアウトとアカウント切替では配送用のUUIDを更新し、
  古い配送・古い通知タップを拒否します。認証トークンをFCMやIntentに入れません。
  OSの「強制停止」中や通知権限を拒否した端末には配信できません。
  Firebase未設定の配布物は動作中のセッション同期だけを使うため、OSによる同期停止後の配送は保証しません。
  連合専用の通知、外部URLからの deep link、共有受信は未対応です。
- 成立したタッチ操作には軽い触覚フィードバック、投稿メニューの長押しには長押しフィードバックを返します。
  スクロール・取り消し・マウス操作では振動しません。端末の触覚フィードバック設定に従います。
- 画像データをセッション内で最大32 MiB・256件までLRUキャッシュし、同じURLの同時取得を共有します。
  失敗した取得は再試行でき、ログアウト時には破棄します。
- Androidの公開画像は、さらにアカウント別の512 MiBのディスクキャッシュへ保存します。
  アプリの再起動後も再利用し、Cache-Control・ETag・Last-Modifiedに従って期限切れを再検証します。
  no-storeの応答はディスクに保存しません。明示的なログアウト時にアカウントのキャッシュを削除します。
  セッションの期限切れではクライアントを閉じ、同じアカウントの再ログイン用にディスクキャッシュを残します。
  キャッシュの有効期限は配信元のHTTPヘッダーに従い、クライアントから長いmax-ageを補いません。
  配信元が有効期間を指定した画像は、その期間が切れるまで削除・差し替え前の内容が残る場合があります。
  backendの署名付きURL生成にはCache-Controlの上書き指定がなく、CDN・オブジェクトの実際のヘッダーは未確認です。
  OSのストレージ管理によって削除されることもあります。
- ファイル選択による添付には対応します。Web 固有のドラッグ＆ドロップとクリップボード画像貼り付け、
  Bubble Chat のタブ離脱通知、アニメーション画像の複数フレーム再生は未対応です。
- Slack 連携の画面は Android にもありますが、「Slack から取り込む」は、ZIP から取り込む方式を廃止したため、Android にはありません。
  管理者の Slack 取り込み画面（「Zoo設定」の「Slack 取り込み」タブ）と、連携ユーザーが非公開チャンネルを取り込む画面は、Web 版だけにあります
  （[Slack からの取り込み](slack-import.md)）。

過去の Web 実験と Android の画面実装は共通ですが、タッチ操作・IME・権限別の全画面の実機検証は別途必要です。

## Shizuku による main の自動更新

「設定 → アプリの更新」から Shizuku の使用を許可し、「自動更新」を有効にします。
ログイン前でも設定できます。Shizuku は別途インストールし、サービスを起動しておく必要があります。
端末の再起動などで Shizuku が停止した場合は、再び起動してください。
自動更新の有効化だけで Shizuku の権限を自動取得することはありません。

- main に Android に関係する変更（`frontend-compose/**`、文言、アイコンなど。CI Android の
  `push` の `paths` と同じ）が入るたびに、テスト・lint 後に固定鍵で署名した release APK を
  ビルドし、GitHub Releases の開発版 `android-main` へ配布します。TUI など Android に関係しない
  変更では、ビルドも配布も動きません。初回配布は main の CI Android を
  `workflow_dispatch` で手動実行しても作成できます。
- APK は `zoo-android-main-<commit SHA>.apk`、更新情報は `update.json` です。
  更新情報には実際のビルドのコミット・バージョン・サイズ・SHA-256 が入ります。
  `android-main` タグ自体は初回作成時のコミットを指す固定の配布チャンネルです。
- バージョンコードは main の first-parent コミット数です。完全な Git 履歴を取得して採番し、
  新しい main のコミットに Android に関係する変更が含まれる古い実行結果は配布しません。関係しない
  変更だけが後から入ったときは、同じ内容のビルドとして配布します。過去のバージョンへ自動で戻しません。
- WorkManager が6時間ごとに、従量制ではないネットワークと十分なバッテリーがあるときに確認します。
  OS のバックグラウンド制限によって実行時刻は遅れることがあります。
  「今すぐ更新を確認」は接続中のネットワークで実行します。
- インストール前にパッケージ名・新しいバージョン・ファイルサイズ・SHA-256・現在の APK と
  同じ署名鍵であることを確認します。APK はアプリ専用キャッシュへ保存し、読み取り用の
  ファイルディスクリプターを Shizuku の UserService へ渡してインストールします。
- 更新の完了後は、Shizuku の UserService が同じ Android ユーザーで Zoo を開き直します。保存した認証情報が有効なら自動ログインします。
  アプリのデータとアカウント別の下書きは維持されます。自動更新は初期状態では無効です。
- Shizuku を使わない場合は、「最新の APK をダウンロード」で `update.json` を確認し、最新の APK を
  ブラウザーで開いてダウンロードします。ダウンロードした APK を開き、Android の標準インストーラーで
  手動更新します。Shizuku の許可や自動更新の設定は不要です。署名鍵が同じ release APK でのみ上書きできます。
- debug APK は署名が異なるため対象外です。最初に署名付き release APK を導入してください。
  debug 版を削除して入れ替える場合は、そのアプリ内データも削除されます。

### 継続署名の設定

GitHub の Repository Actions Secrets に次の4個を登録します。

| Secret | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | 継続して使用する keystore ファイルの Base64（改行なし） |
| `ANDROID_STORE_PASSWORD` | keystore のパスワード |
| `ANDROID_KEY_ALIAS` | 署名鍵の alias |
| `ANDROID_KEY_PASSWORD` | 署名鍵のパスワード |

署名鍵は Git 管理に含めません。鍵一式を安全な場所へ保存し、同じ鍵を使い続けてください。
Secrets がない場合、main の配布ジョブは失敗し、署名の異なる APK を代わりに配布しません。
ローカルで署名する場合は `ZOO_ANDROID_KEYSTORE`（ファイルパス）、
`ZOO_ANDROID_STORE_PASSWORD`、`ZOO_ANDROID_KEY_ALIAS`、`ZOO_ANDROID_KEY_PASSWORD` を
設定し、`-Pzoo.android.versionCode=<整数>` と `-Pzoo.android.versionName=<表示名>` を指定して
`:androidApp:assembleRelease` を実行します。

Shizuku を使用するインストールは、実際に Shizuku が稼働する Android 端末での検証が必要です。

### Shizuku の接続と実装の根拠

Shizuku の Binder はプロセス起動後に Provider へ届きます。WorkManager から起動したときも、
未到着を即座に権限不足と判断せず、受信リスナーで最大5秒待ちます。待機終了・キャンセル時には
リスナーを解除し、到着後に使用許可を確認します。UserService の接続は最大20秒で打ち切り、
接続できなかった場合は更新画面へエラーを保存します。Worker 自体のキャンセルはそのまま伝えます。

調査した資料と実装例:

- [Shizuku API の公式ガイド](https://github.com/RikkaApps/Shizuku-API/blob/master/README.md):
  Binder の生存期間・使用許可、ADB と root の違い、UserService、destroy の AIDL transaction ID。
  ADB はアプリ専用ファイルを直接読めないため、APK のパスではなく FD を渡します。
- [ShizukuProvider](https://github.com/RikkaApps/Shizuku-API/blob/master/provider/src/main/java/rikka/shizuku/ShizukuProvider.java):
  起動時の Binder 配信は Provider への呼び出しで行われ、Provider の onCreate 完了は受信完了を意味しません。
- [Obtainium の ShizukuInstaller](https://github.com/ImranR98/Obtainium/blob/35c3e7fea4f341a716eca4bb3fc625319ce965ab/lib/installers/shizuku_installer.dart):
  一時的な Binder 未到着を再確認し、権限拒否や古いサービスと分けて扱います。

## Androidのプッシュ通知の設定

`Zli-UoA/zoo2-infra` の `terraform/firebase` で、Firebaseプロジェクト、Androidアプリ `works.zli.zoo`、

APKのビルドでは次の公開識別子を4つまとめて設定します。全て未設定ならFCMを無効にしてビルドでき、

| 環境変数 | Firebase Android設定の値 |
| --- | --- |
| `ZOO_ANDROID_FIREBASE_APP_ID` | `mobilesdk_app_id` |
| `ZOO_ANDROID_FIREBASE_API_KEY` | `api_key.current_key` |
| `ZOO_ANDROID_FIREBASE_SENDER_ID` | `project_info.project_number` |

必要な権限は当該プロジェクトの `cloudmessaging.messages.create` です。
この値は `Zli-UoA/zoo2-infra` のsops暗号化Secret（追加するSecret名 `zoo2-fcm`、キー `FCM_SERVICE_ACCOUNT_JSON`）

登録は既存の認証付き `/api/push/config` と `/api/push/subscriptions` を使います。
`fcmProjectId`がAPKのプロジェクトと一致し、通知が許可されている場合だけ、
`transport: "fcm"`、`endpoint: "fcm:<registration-token>:<binding-uuid>"` を登録します。
`fcmDmCalls` はサーバーでAndroidへのDM着信のFCM配送を利用できることを表します。値が `true` で端末のDM着信が有効な場合は `fcm:<registration-token>:<binding-uuid>:dm-calls` を登録し、設定を切り替えると旧endpointを削除して新しいendpointを登録します。DM着信とその取り消しは接尾辞がある購読にだけ配送します。旧版は通常のFCM通知を受け取れます。
Firebase登録トークンとendpointは配送先の秘密情報としてログや同期データへ出しません。
未設定・登録失敗時もセッション同期の通知は維持し、ログイン・復帰・接続回復・動作中のトークン更新で登録を再確認します。
アプリが終了している間にFCMトークンが更新された場合は、次のログイン復元で再登録します。

FCMは既存の通知作成・DND・本文の閲覧条件を使い、暗号化チャンネルの本文は「新しいメッセージ」のまま送ります。
DM着信を有効にしたAndroid購読には、DMの着信を高優先度、取り消しを通常優先度で配送します。連合専用通知は配送対象に含めません。Web Pushの鍵・API・配信は維持します。
React・TUI・デスクトップの通知作成・取得経路は変えません。Android専用の配送手段なのでTUIの機能変更・版更新は不要で、`make tui-check`で互換性を確認します。
DBは既存の `push_subscriptions` と登録・解除・利用者別配送のクエリを再利用し、スキーマ・索引は変更しません。
総購読数N、対象利用者の購読数Sに対し、主キー登録・解除はO(log N)、
配送は既存の `idx_push_subscriptions_user_id` によるO(log N + S)です。新規の常設接続やポーリングはありません。

実機では権限を許可してから別ユーザーでメンション・DM・返信・リアクションを作り、
表示中、別アプリ使用中、画面ロック中、通常のプロセス終了後で通知とタップ先を確認します。

### Android の画像キャッシュ

取得済みの添付画像、公開画像、外部連合絵文字、通知画像は、サーバー・アカウント別のディスクキャッシュに保存する。「画像キャッシュ」はオフまたは128 MiB〜2 GiBを選べる。既定は512 MiBで、上限を超える場合は最後の利用が古い画像から削除する。画像種別やHTTPの鮮度にかかわらず、保存済みの本文を通信せずに使う。添付画像の閲覧権限は表示と並行してオンライン時に確認し、明示的な閲覧拒否が確認できた画像は表示と保存から取り除く。ログアウト時はアカウントの保存画像を削除する。画像を再試行するときは、同じ取得先のETagまたはLast-Modifiedがあれば条件付きGETを送り、304では保存済みの本文を再利用する。検索では同期済みの元の本文から確認できた外部リンクに限って取得済みのSummalyカードを表示する。リンクの判定結果は会話を離れたあともセッション内で保持し、検索結果の更新日時が一致する場合に使う。

外部画像は配備先の HTTPS media-proxy で取得する。元画像の URL が HTTP の場合も Android からの通信は HTTPS のプロキシ宛てとする。保存済みのプロキシ設定は24時間後のキャッシュミス時に再確認する。確認失敗時は保存済み設定を維持し、30秒後から再試行する。404は配備先で未設定とみなし、保存済み設定を消して30秒後から再試行する。Pushは本文を先に表示し、設定の確認は通信開始から700ms、待機込みで750msまでとする。確認がタイムアウトすると保存済み設定を使い、設定がなければ本文のみ表示する。

公開画像は元画像のURLでディスクキャッシュを引く。署名付き添付は添付IDと画像の種類でキャッシュを引き、未保存の場合は署名済みの配信先から直接取得する。旧バージョンから更新するときは保存済みの署名付き添付を引き継ぎ、旧HTTPキャッシュにあった画像は次に表示したときから新しいキャッシュへ保存する。

Androidの投稿・引用にはアバターを表示し、APub・Emoji Kitchenのリアクション画像にも対応する。外部画像プロキシへの同時取得は端末内で2件までで、429・5xxは1回だけ再試行する。Pushは取得枠を待たず、枠が空いていない場合も本文通知は表示済みとなる。

### Android のログイン診断

外部Wi-Fiの利用登録が検出された場合は接続を案内し、「それでも試す」でブラウザー認証の準備を続行できる。認証設定の取得では接続できるIPアドレスを試し、成功したアドレスは同じホストのDNS応答に含まれる間、トークン取得・更新で優先する。
