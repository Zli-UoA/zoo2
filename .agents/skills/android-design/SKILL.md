- [Frontend consistency](../frontend-consistency/SKILL.md) と [Storybook coverage](../storybook-coverage/SKILL.md)

## 設計する

1. Zoo Webの用語、コンテンツ構造、白・黒の本文面と黄色いブランド色を共有する。上部の光はヘッダーで終える。ライト・ダーク・端末設定に対応する。
2. 画面の目的に合わせて余白を決める。連続する投稿・会話・通知は余白と罫線で区切り、操作シートや選択状態には面を使う。通知固有の構造を投稿の前提にしない。
3. 下部のホーム・チャンネル・通知・Bubble・設定は各トップだけに表示する。子画面は戻る操作で親の位置へ戻す。ヘッダーは読み進めると隠れ、逆方向のスクロールで戻す。
4. 意味が明確な操作にはアイコンと読み上げ名を付ける。タブや意味の曖昧な操作には文字を使う。単独の主操作は文字幅に応じた中央配置にする。
5. 会話入力は待機・入力中・全画面を共有状態で描画する。つまみは上端、全画面の操作列は下端。入力面・つまみ・境界は無彩色にし、黄色は使える送信操作に絞る。IME表示時は操作列をキーボードの上へ置く。
6. ジェスチャーと画面遷移は既存の操作・Androidの戻る操作と競合させない。長押しの操作はTalkBackのカスタムアクションでも提供する。触覚は端末設定に従う。

通知画面では、前面の表示範囲に入った通知を自動で既読にする。既読にするためのボタンは置かない。

画面部品の文字は本文400、補助見出しと操作500、タイトルと未読の強調600を基準にする。

チャンネル一覧のチャンネルとDMは、名前を1行で表示し、未読がある場合だけ太字にする。未読状態は読み上げにも渡す。説明文と区切り線を省き、タップ領域は48dp以上を確保する。

アイコンボタンは操作領域48dp、アイコン24dp、背景付きなら48dpの円。文字ボタンは高さ48dp以上で幅は内容に合わせる。ナビゲーションと入力欄のつまみは画面別の基準を使う。

設定画面では区切り線を使わず、見出しと余白で項目をまとめる。

起動・セッション復元・権限表示・アプリ更新などの Activity 側の UI も画面と合わせて設計する。バージョンと更新・通知権限の入口は設定画面に置く。

## 新規画面・機能の実装順序

1. **合意した画面を起点にする。** トップ、子画面、一時的な操作面、OS連携のどれかを決め、合意画像を参照してAndroid用の画面と必要なコンポーネントを組む。既存UIの形状、配置、部品の都合を画面設計の前提にしない。
2. **接続前のComposeで確認する。** 仮の表示データと操作コールバックを使い、認証・同期・通信なしで描画する。通常、空、読み込み、エラー、権限拒否、入力中、無効などの該当状態を、ライト・ダークの実キャプチャで合意画像と比較する。部品の形、情報の位置、余白、操作状態の大きな差をここで解消する。
3. **UIが必要とする契約を決める。** 表示データ、発生する操作、戻ったときに保持する位置や下書きを明示する。ジェスチャーの確定・中断とOSの戻るとの競合も決める。
4. **既存のロジックを検討して接続する。** UIの契約に合うSession、Repository、機能コントローラー、端末連携をアダプターで接続する。Webの用語とデータの意味を揃え、既存処理の形に合わせて合意済みのUIを変えない。
5. **接続後の実画面で再確認する。** 同じ状態・幅・テーマで撮影し、接続前のComposeと合意画像を照合する。実際の操作はテストと端末で確認し、PRに実画面を添付する。

## アーキテクチャ

- `Session`、`Repository`、機能ごとのコントローラーは認証、同期、書き込み、キャッシュとエラーを所有する。Android側はIntent、権限、IMEなどの端末連携を担当する。
- Composeの画面レイアウトは、表示データと操作コールバックを受け取る。表示上の選択・スクロール・アニメーションを画面内で持ってよい。送信・画像選択・権限要求の副作用はコールバックを介して実行する。
- 既存画面を組み直す場合も、下書き、選択範囲、操作の無効状態、戻り先、セッション境界の契約を明示して移植する。

## 実装・確認する

- `Session`、`Repository`、下書き、添付、送信の所有者を再利用する。画面の状態・描画と通信を分ける。
- Androidの既存部品は合意した見た目と操作仕様に合う場合に使う。汎用入口にも変更が必要なら `Ui.kt` などからAndroidの描画を分ける。通常のタップ対象は48dp以上。表示サイズと区別し、文字倍率や訳文に合わせて折り返す。
- 320dpと600dp、ライト・ダーク、大きな文字、オフライン、IME・TalkBackを確認する。
- デザインや操作を更新したら、サンプル集の該当画面と実キャプチャも更新する。合意したデザインの変更はモックにも反映し、端末検証が必要な箇所を明記する。
- [Android ビルド](../../../docs/android.md#ビルド)のテストとlintを実行する。PRに実際のCompose画面のスクリーンショットを添付し、実機で未確認の動作を明記する。
