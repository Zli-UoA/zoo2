# Android の UI と操作体験

## 先に読む

- [Android デザイン](../../../docs/android-design.md) の画面別ルール・検証条件
- [UI デザインサンプル](../../../docs/android-design-samples.md) のデザインモックと実キャプチャ
- `frontend-compose/src/commonMain/kotlin/zoo/AndroidDesign.kt` の共通トークン
- [Frontend consistency](../frontend-consistency/SKILL.md) と [Storybook coverage](../storybook-coverage/SKILL.md)

## 設計する

1. Zoo Webの用語、コンテンツ構造、白・黒の本文面と黄色いブランド色を共有する。投稿画面の上部の光はヘッダーで終える。通知画面ではステータスバーの背面から一覧の上端まで光をつなげ、本文面の色へなだらかに戻す。ライト・ダーク・端末設定に対応する。
2. 画面の目的に合わせて余白を決める。画面全体で項目間の区切り線を省き、余白と見出しでまとまりを示す。操作シートや選択状態には面を使う。通知固有の構造を投稿の前提にしない。
3. 下部のホーム・チャンネル・検索・通知・Bubble・設定は各トップだけに表示する。子画面は戻る操作で親の位置へ戻す。ヘッダーは読み進めると隠れ、逆方向のスクロールで戻す。
4. 意味が明確な操作にはアイコンと読み上げ名を付ける。標準操作とチャンネルの # には Material Design Icons のアウトライン版を使う。ログイン・保存・投稿などの文字付きアクションボタンは600ウェイトとし、動作を示すアイコンを添える。タブや選択肢には必要なラベルを使う。単独の主操作は文字幅に応じた中央配置にする。
5. 会話入力は待機・入力中・全画面を共有状態で描画する。チャンネル会話とスレッドのつまみは入力中・全画面のときに上端に表示し、待機中は余白ごと省く。全画面の操作列は下端。入力の操作列は画面の左右と下から4dp内側に置く。入力面・つまみ・境界は無彩色にし、黄色は使える送信操作に絞る。IME表示時は操作列をキーボードの上へ置く。
6. ジェスチャーと画面遷移は既存の操作・Androidの戻る操作と競合させない。長押しメニューは操作名の左にアイコンを添え、TalkBackのカスタムアクションでも提供する。触覚は端末設定に従う。

通知画面では、前面の表示範囲に入った通知を自動で既読にする。既読にするためのボタンは置かない。同じ投稿への同じ種類のアクションをまとめる。Web の通知行を参考に、左に送信者のアバターとアクションバッジ、右に名前・日時・プレビュー・遷移先を置く。複数の送信者のアバターも行内に表示する。リアクション通知では実際に使われた絵文字をアクション文の隣に表示する。未読は文字を出さず、ドットと読み上げ状態で示す。

画面と入力欄は同じロケールを使い、アプリの言語に合うAndroidのフォントフォールバックを適用する。

画面部品の文字は本文400、ユーザー名・補助見出し・操作500、タイトルと未読チャンネルの強調600を基準にする。APub・チャンネル・DM・スレッド・Bubbleの投稿と、引用・通知の本文プレビューでは、投稿者名と本文の基準サイズを16spにそろえ、投稿者名を600で表示する。
ホームの投稿作成では、ヘッダーに公開範囲のアイコンとActivityPubロゴを置く。公開範囲はアイコンから選択する。連合配信はオンでロゴ本来の色、オフでグレーとし、状態を読み上げに渡す。

絵文字入力とリアクション追加には共通の下部ピッカーを使い、冒頭はタブから始める。ピッカーの名前は読み上げに渡す。標準絵文字、ワークスペースのカスタム絵文字、Emoji Kitchenをタブで分け、名前や別名で検索できるようにする。検索欄は無彩色の入力面と虫眼鏡を使い、浮き上がるラベルは使わない。標準一覧はオフラインでも使えるようにする。絵文字はシートの表示幅に合わせて列数を増減し、タップ領域は48dp以上を保つ。

APub投稿は再投稿者と引用元を表示する。再投稿者はアバター列を含む投稿全体の上に置く。APubとチャンネルの画像は本文の下でプレビューし、動画はタップでアプリ内プレイヤーを開く。センシティブなメディアはタップするまで内容を表示しない。
APubの画像は1枚なら元の幅:高さを3:4〜16:9に収める。2枚以上は全体を16:9にし、2枚は左右、3枚は左1枚・右2段、4枚は2×2とする。5枚以上は右下に残りの枚数を重ねる。チャンネルでは元の縦横比を保って本文の左端に揃え、高さ上限まで縮小して全体を見せる。複数枚は同じ行を横にスクロールする。どちらも読み込み前から画像枠を確保し、使える場合はBlurHashを表示する。センシティブ画像には画像内右上に表示切り替えを置く。

画像をタップすると選んだ画像から全画面で開く。画像名は表示せず、横ドラッグで同じ投稿の前後の画像へ移動し、上下のドラッグで会話に戻る。ドラッグ中は画像を指に追従させる。Summalyの画像は周囲の余白と枠線を置かず、サイト名とタイトルは各1行、説明は3行までで省略する。

投稿・会話・スレッドの本文は共通のMFMパーサーを使い、入れ子の装飾、リテラル、コード、リンク、カスタム絵文字を同じ規則で扱う。リンクプレビューとアプリ連携カードは本文から区別できる中立色の面にまとめる。描画できる連携カードがある場合は代替本文の重複を避け、形式を読めない場合は代替本文を残す。

APub投稿のサーバー帯はサーバーが返すテーマカラーを淡いグラデーションに使う。色が取得できない場合は標準色を使う。上下パディングを置かず、文字は1行に収める。#チャンネル名とサーバー名は同じ文字サイズ・行高を使い、1行目からの間隔と2行目の高さをそろえる。#チャンネル名の帯には淡い無彩色を使う。
ホーム・投稿詳細・プロフィールでは各投稿の下に、返信・再投稿・リアクション追加・その他のアイコンボタンを、左右の端が投稿本文の領域と揃うように等間隔で置く。アイコンは14dp、列の高さは36dp、下の余白は4dpとする。タップ領域はComposeの最小サイズへの拡張を使う。

チャンネル一覧のチャンネルとDMは、名前を1行で表示する。チャンネル名は未読時だけ太字にし、個人DMのユーザー名は500で表示する。未読状態は読み上げにも渡す。説明文と区切り線を省き、タップ領域は48dp以上を確保する。

アイコンボタンは操作領域48dp、アイコン24dp、背景付きなら48dpの円。文字に並ぶ操作アイコンは15–16spの文字に合わせて16dp、11–12spの補助情報のアイコンは12dpを基準とする。チャンネル・DM作成には Material の Add（＋）を使う。文字ボタンは高さ48dp以上で幅は内容に合わせる。ナビゲーションと入力欄のつまみは画面別の基準を使う。

背景付きの操作バーは、ボタンの輪郭が背景の縁に接しないように余白を取る。ホームの投稿作成バーは四辺8dpを基準にする。

設定画面では区切り線を使わず、見出しと余白で項目をまとめる。

起動・セッション復元・権限表示・アプリ更新などの Activity 側の UI も画面と合わせて設計する。バージョンと更新・通知権限の入口は設定画面に置く。

## 新規画面・機能の実装順序

1. **合意した画面を起点にする。** トップ、子画面、一時的な操作面、OS連携のどれかを決め、合意画像を参照してAndroid用の画面と必要なコンポーネントを組む。既存UIの形状、配置、部品の都合を画面設計の前提にしない。
2. **接続前のComposeで確認する。** 仮の表示データと操作コールバックを使い、認証・同期・通信なしで描画する。通常、空、読み込み、エラー、権限拒否、入力中、無効などの該当状態を、ライト・ダークの実キャプチャで合意画像と比較する。部品の形、情報の位置、余白、操作状態の大きな差をここで解消する。
3. **UIが必要とする契約を決める。** 表示データ、発生する操作、戻ったときに保持する位置や下書きを明示する。ジェスチャーの確定・中断とOSの戻るとの競合も決める。
4. **既存のロジックを検討して接続する。** UIの契約に合うSession、Repository、機能コントローラー、端末連携をアダプターで接続する。Webの用語とデータの意味を揃え、既存処理の形に合わせて合意済みのUIを変えない。
5. **接続後の実画面で再確認する。** 同じ状態・幅・テーマで撮影し、接続前のComposeと合意画像を照合する。実際の操作はテストと端末で確認し、PRに実画面を添付する。

## アーキテクチャ

- `Session`、`Repository`、機能ごとのコントローラーは認証、同期、書き込み、キャッシュとエラーを所有する。Android側はIntent、権限、IMEなどの端末連携を担当する。
- Composeの画面レイアウトは、表示データと操作コールバックを受け取る。表示上の選択・スクロール・アニメーションを画面内で持ってよい。送信・画像選択・権限要求の副作用はコールバックを介して実行する。
- 既存画面を組み直す場合も、下書き、選択範囲、操作の無効状態、戻り先、セッション境界の契約を明示して移植する。

## 実装・確認する

- `Session`、`Repository`、下書き、添付、送信の所有者を再利用する。画面の状態・描画と通信を分ける。
- Androidの既存部品は合意した見た目と操作仕様に合う場合に使う。汎用入口にも変更が必要なら `Ui.kt` などからAndroidの描画を分ける。通常のタップ対象は48dp以上。表示サイズと区別し、文字倍率や訳文に合わせて折り返す。
- 320dpと600dp、ライト・ダーク、大きな文字、オフライン、IME・TalkBackを確認する。
- デザインや操作を更新したら、サンプル集の該当画面と実キャプチャも更新する。合意したデザインの変更はモックにも反映し、端末検証が必要な箇所を明記する。
- [Android ビルド](../../../docs/android.md#ビルド)のテストとlintを実行する。全画面を対象とするPRでは各画面と主要状態のライト・ダークのCompose実キャプチャを本文に掲載し、実機で未確認の動作を明記する。

## 操作と端末連携の確認

- 会話の横スワイプは指に追従させ、左へしきい値を越えて離したときに確定する。途中で戻した場合とキャンセル時は元の位置に戻し、触覚は確定時だけ設定に従って鳴らす。縦スクロールやシステムの戻るジェスチャーと競合しないことを確認する。
- ホームと会話は本文のスクロールでヘッダーを隠し、逆方向で再表示する。スレッドの入口と戻りには逆向きの遷移を使い、元の会話のスクロール位置と下書きを復元する。端末でアニメーションを無効にした場合も確認する。
- ホーム投稿内に端末の最近の写真を出し、Android のフォトピッカーへの入口も残す。写真のアクセス範囲を限定した場合、拒否した場合、投稿に添付できた場合を確認する。
- ブラウザ認証からの App Links 復帰、画像付き OS 通知から該当投稿を開く動線、着信の応答と通話中の操作は、接続した環境の端末で個別に確認する。
- チャンネル名のヘッダーから設定を開く。メンバー一覧とメンバー操作は権限に応じて表示し、サーバー側でも権限を適用する。一般メンバー・管理可能なユーザー・アーカイブ済みの各状態で確認する。
- 通話は中央に相手のアバターを表示する。着信中の波紋は一定のリズムにし、接続後は相手の受信音声に連動させる。無音時と端末で動きを減らす設定が有効な場合は静止する。
- ロック画面の着信もアプリ内と同じ画面部品を使う。通話中はアプリ内の最小化と対応端末のPiPから通話へ戻れるようにし、通話エラーと全画面着信の設定入口を表示する。
- 着信の応答と拒否は画面下部の左右に並べ、緑と赤の円形ボタンに白い電話アイコンを置く。各アイコンの下に短いラベルを添える。
- Web と共通の投稿・通知・スレッド操作は既存 API の状態と権限を使う。自分の投稿だけに編集・削除を出し、フォロー申請に回答したら操作を閉じる。暗号化された会話の本文をリンクプレビューの取得先へ送らない。

- プロフィールではアバターと表示名、ユーザー ID、自己紹介、投稿を同じスクロール面に置く。連合アカウントの ID はホストまで表示する。フォローと公開プロフィールへの入口は利用できる場合に表示する。
- APub 投稿の1行目は表示名と ID を左、日時と公開範囲アイコンを右に置く。2行目は #チャンネル名、またはサーバー名の帯を表示する。
